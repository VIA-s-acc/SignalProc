## Назначение

Прочитать WAV-файл в сигнал $x_c[n]$ типа double: по одному массиву на канал, шкала $[-1, 1)$ независимо от исходного формата (PCM 8/16/24/32 бит, float32/64, A-law, $\mu$-law). Заодно посчитать длительность, пик и число отсчётов на полной шкале.

## Формулы

Целочисленный PCM из $b$ бит со знаком делится на $2^{b-1}$, 8-битный (без знака) сначала сдвигается на 128:

$$x[n] = \frac{q[n]}{2^{b-1}}, \quad -2^{b-1} \le q[n] \le 2^{b-1}-1, \qquad x_{\mathrm{u8}}[n] = \frac{q[n]-128}{128}$$

Float32 и float64 переносятся как есть, $x[n] = q[n]$; A-law и $\mu$-law сначала разворачиваются в 16 бит, затем $x[n] = q_{16}[n] / 2^{15}$.

Длительность и пик канала $c$:

$$T = \frac{N}{f_s}, \qquad P_c = 20 \log_{10} \max_n \lvert x_c[n] \rvert \;\text{дБFS}$$

Полная шкала — это $x_{\mathrm{fs}} = 1 - 2^{1-b}$ для целых форматов и $1$ для float; счётчик клиппинга $K_c$ — число отсчётов с $\lvert x_c[n] \rvert \ge x_{\mathrm{fs}}$.

## Алгоритм и стоимость

1. Заголовок разбирается библиотекой dr_wav (RIFF и extensible); формат определяется по паре «тег, число бит». Неподдерживаемая пара даёт ошибку, а не падение.
2. Данные читаются блоками по $2^{16}$ кадров. В файле каналы перемежаются, $s[nC + c] = x_c[n]$; каждый отсчёт декодируется в double и раскладывается по своему каналу.
3. После каждого блока сообщается прогресс и проверяется отмена.
4. Пустой файл и файл без каналов — ошибка.
5. Один проход по каждому каналу даёт пик, RMS, постоянную составляющую и $K_c$.

FLAC и MP3 читает та же точка входа `read_audio`. Формат она узнаёт по первым байтам файла (`RIFF`, `fLaC`, `ID3` или заголовок кадра MP3), а не по расширению, так что FLAC с расширением `.wav` тоже откроется. FLAC (библиотека dr_flac) сжат без потерь: $b$-битные отсчёты делятся на $2^{b-1}$, как у WAV, и файл даёт ровно те же числа, что WAV, из которого он сделан. MP3 (dr_mp3) сжат с потерями: декодер выдаёт float32, а задержку кодера в начале и добивку в конце убирает по заголовку LAME, поэтому длина сигнала совпадает с исходной.

Время $O(N\,C)$, память $8\,N\,C$ байт: 16-битный файл в памяти в четыре раза больше, чем на диске. Резервируется не больше $2^{24}$ кадров на канал, чтобы испорченный заголовок не выделил гигабайты.

## Проверки

Численной проверки в интерфейсе у этого блока нет: его правильность закрепляют тесты.

Тесты читают эталонные файлы всех форматов и сверяют формат, число каналов, частоту, число кадров и сами отсчёты (побитно) с эталоном. Повреждённые файлы дают ошибку, а не падение. Два канала `test.wav` остаются раздельными. Чтение сообщает прогресс и отменяется. `probe_wav` читает только заголовок. Для FLAC и MP3 (`tests/io/test_audio_read.cpp`): FLAC 16 бит совпадает с исходным WAV отсчёт в отсчёт, 24-битный и 6-канальный сохраняют разрядность и порядок каналов; MP3 той же длины, что исходник, и отличается от декодирования ffmpeg меньше чем на $10^{-4}$; формат определяется по содержимому, а текстовый файл с расширением `.mp3` даёт ошибку.

## Реализация

Декодирование отсчётов целочисленного PCM в шкалу $[-1, 1)$: эти функции `read_wav` вызывает для каждого отсчёта блока.

```cpp
double decode_pcm_u8(const unsigned char* p) { return (static_cast<double>(p[0]) - 128.0) / 128.0; }

double decode_pcm_s16(const unsigned char* p) {
    return static_cast<std::int16_t>(static_cast<std::uint16_t>(p[0] | p[1] << 8)) / 32768.0;
}

double decode_pcm_s24(const unsigned char* p) {
    auto v = static_cast<std::int32_t>(std::uint32_t{p[0]} | std::uint32_t{p[1]} << 8 | std::uint32_t{p[2]} << 16);
    if (v & 0x800000) v -= 0x1000000;
    return v / 8388608.0;
}

double decode_pcm_s32(const unsigned char* p) { return static_cast<std::int32_t>(le32(p)) / 2147483648.0; }
```
