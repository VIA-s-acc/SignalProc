# Signals и Python

[English](python.en.md)

Signals обменивается с numpy, scipy и pywt файлами `.npy` и `.npz`. Числа хранятся восемью байтами double, как есть, без перевода в текст. `np.load(path, allow_pickle=False)` открывает любой файл, который записала программа, а программа открывает файлы, записанные `np.save`, `np.savez` и `np.savez_compressed`.

## Выгрузка

| Где | Что делает |
|---|---|
| `signals run graph.sig --npz out.npz` | все щупы в одном файле; ключ — имя щупа, точка и ключ значения: `clean.x`, `clean.rate` |
| `signals run graph.sig --probe-dir dir --probe-format npy` | щуп-сигнал в `<имя>.npy`, остальные щупы в `<имя>.npz`; `wav` (по умолчанию) и `json` — как раньше |
| `signals dwt in.wav --wavelet db4 --levels 5 -o out.npz` | коэффициенты разложения; с другим расширением — JSON, как раньше |
| `signals filter info db4 -o bank.npz` | банк фильтров вейвлета |
| блок `export(format=npy)` | отсчёты сигнала |
| блок `export_report(format=npz)` | поля отчёта |
| «Конвейер», `x` | щуп-сигнал в `.npy`, любой щуп в `.npz` |
| «Разложение», `N` | показанные коэффициенты |
| «Фильтры», `N` | банк выбранного вейвлета |
| меню графика «Сохранить график» с путём `*.npz` | ряды графика `x0`, `y0`, `x1`, `y1`… и их имена `names`; у карты — `z`, `x`, `y` |

## Загрузка

- Блок `wav` и `o` на вкладке «Сигнал» открывают `.npy` и `.npz` так же, как WAV: формат узнаётся по содержимому файла.
- Частота берётся из ключа `rate`. У `.npy` её нет: у блока задайте параметр `rate`, а вкладка «Сигнал» спросит её сама. Если частота в файле расходится с параметром `rate`, это ошибка.
- Из `.npz` берётся массив `x`. Если такого ключа нет, берётся единственный массив. Другой массив выбирает параметр `key`.
- Массив `(N,)` — один канал, `(C, N)` — C каналов. Массив больше чем из 64 строк — ошибка: скорее всего, это `(N, C)` из soundfile, и его нужно сохранить как `x.T`.
- Сжатый элемент `.npz`, который разворачивается больше чем в 256 МиБ и больше чем в 200 раз, не читается: так выглядит zip-бомба. Большой массив из нулей сохраняйте `np.savez`, без сжатия.
- Блок `coeffs_file` читает коэффициенты из `.npz`, записанного Signals или pywt. Если в файле нет ключей `wavelet`, `mode` и `rate`, их задают параметры блока. Полосы проверяются на согласие с вейвлетом пробным обратным преобразованием.

## Раскладка ключей

| Значение | Ключи |
|---|---|
| сигнал | `x` — `(N,)` или `(C, N)`; `rate` |
| коэффициенты `dwt` и лифтинга | `cA{J}`, `cD{J}` … `cD1` |
| коэффициенты `swt` | `cA{J}`, `cD{J}` … `cD1`, как `pywt.swt(..., trim_approx=True)`; `norm` |
| коэффициенты `wpt` | путь узла пакета: `aa`, `ad`, `da`, `dd`…; `length` обязателен |
| коэффициенты `dtcwt` | `cA{J}`, `re_cD{j}` и `im_cD{j}` |
| у всех коэффициентов | `wavelet`, `mode`, `rate`, `transform`, `length`, `detail_sign` |
| отчёт | по ключу на поле, `passed`, `fields` — порядок полей |
| банк фильтров | `dec_lo`, `dec_hi`, `rec_lo`, `rec_hi`, `name` — как `pywt.Wavelet(...).filter_bank` |

Многоканальные коэффициенты — массивы `(C, len)`, одноканальные — `(len,)`.

```python
import numpy as np, pywt
f = np.load("out.npz", allow_pickle=False)
x = pywt.waverec([f["cA5"], f["cD5"], f["cD4"], f["cD3"], f["cD2"], f["cD1"]], str(f["wavelet"]), mode=str(f["mode"]))
b = np.load("bank.npz")
w = pywt.Wavelet(str(b["name"]), filter_bank=[b[k] for k in ("dec_lo", "dec_hi", "rec_lo", "rec_hi")])
```

## Скрипт по графу: `signals python`

```bash
signals python examples/first_steps.sig
python examples/first_steps.py
```

Команда выполняет граф так же, как `signals run`, и пишет рядом с ним скрипт `first_steps.py` и файл данных `first_steps.npz`. Путь выбирает `-o`, параметры меняет `--set узел.параметр=значение`. Ошибка в графе даёт тот же текст и код, что `signals run`, и файлов не появляется. Имя скрипта не может совпадать с модулем Python (`math.py`, `signal.py`, `numpy.py`): из той же папки Python загрузил бы скрипт вместо модуля, поэтому команда такое имя не примет — задайте другое через `-o`.

Скрипт зависит только от numpy, scipy и PyWavelets и повторяет граф узел за узлом: над каждым узлом стоит его строка из `.sig`, переменная названа по узлу. Переменные графа (`let`) стоят в начале скрипта как переменные Python (`fs = 8000`, `half = fs / 2` — в порядке, в каком они друг от друга зависят), а в тетради — в ячейке «Параметры графа». Имя, занятое в Python, получает `_` в конце: `let np = 3` становится `np_ = 3`. Параметр, заданный переменной, ссылается на неё: `level=lv`. Скрипт помнит значения, по которым построен (`GRAPH`). Если их поменять, он пишет «Параметры изменены: сверка с программой пропущена…», считает по новым значениям и завершается с кодом 0. Где у блока есть функция pywt или scipy с теми же числами, вызывается она; остальные блоки записаны короткими функциями на numpy в начале файла. Сигнал в скрипте — массив `(C, N)`, коэффициенты — список полос, как у `pywt.wavedec`, отчёт — словарь полей.

В `.npz` лежит только то, что Python не повторит сам:

- звук, который scipy не читает в те же числа: FLAC, MP3, µ-law и A-law;
- списки параметров длиннее 64 чисел и фильтры вейвлетов, у которых pywt расходится с Signals: симлеты (см. ниже) и свои банки;
- значения для сверки.

Шум (`gen`, `add_noise`) и дизеринг (`quantize`, `wav_out`) скрипт считает сам тем же генератором, что программа, — `mt19937_64` и полярный метод, переписанные на numpy, дают те же числа бит в бит.

### Живой скрипт

Скрипт не повторяет прогон числами, а считает его заново: каждый параметр узла и каждая переменная графа — значение Python, и всё, что из них выводится, считается в скрипте.

- **Параметры — значения Python.** Форма блока пишет параметр литералом (`0.5`), переменной (`fs`) или выражением (`fs / 8`). Длины считаются в скрипте (`samples_count(0.25, 8000)`), секунды переводятся в отсчёты по частоте входа (`as_samples("0.1s", x_fs)`), фильтры проектирует scipy, окна и сетки частот строит numpy.
- **Частота и сведения о коэффициентах.** У каждого сигнала есть частота `x_fs`, у коэффициентов — словарь `c_meta`: вейвлет, режим продолжения, длина, частота. Обратное преобразование, порог и полосы берут их оттуда, поэтому новая частота или новый вейвлет выше по графу доходят до всех узлов ниже.
- **Вейвлет из переменной** пишется `wavelet(имя)`. Функция берёт фильтры Signals из `.npz`, если такой вейвлет был в графе или это симлет, иначе — `pywt.Wavelet(имя)`, а для имени, которого нет нигде, останавливается с понятной ошибкой.
- **Что остаётся данными.** Только внешние файлы: звук, который scipy не читает сам, массивы `.npy`/`.npz` и фильтры из «Моих фильтров». Чтобы взять другой файл, замените путь или массив.

Поменяли переменную графа в начале скрипта — он пересчитает всё, что от неё зависит, и пропустит сверку (см. выше про `GRAPH`). Число в строке узла тоже можно поправить, и всё ниже пересчитается, но сверка тогда покажет расхождение с программой: она сравнивает с прогоном по графу. Это проверяет CI: для каждого параметра каждого блока тест делает параметр переменной, ставит в скрипт второе значение и сравнивает результат с `signals run --set` на этом значении. Восемь параметров проверить так нельзя, их список с причинами — в `tests/python/live_exceptions.txt`: `idwt.wavelet` и `iswt.wavelet` только проверяют коэффициенты, `idwt.ext` влияет лишь при `periodization`, у `mid_side` кодирование и декодирование совпадают, `wav_out.bits`, `dither` и `seed` меняют только записанный файл, а условие `assert.expr` переводится в строку кода Python при создании скрипта — менять его нужно там.

В «Конвейере» то же делает `P` или пункт палитры «Конвейер: выгрузить в Python…»: путь с `.py` даёт скрипт, с `.ipynb` — тетрадь. Выгружается граф, открытый в редакторе, вместе с несохранёнными правками. Инспектор показывает для выбранного узла строку «В Python», а `signals explain <блок>` — Python-форму блока с параметрами по умолчанию.

### Свои блоки

Каждое определение `block` становится одной функцией Python с тем же именем, а вызовы вызывают её со своими аргументами:

```python
def bank_level(x, x_fs, wavelet_="haar"):
    ...
    return sum_, sum__fs, da, da_fs, dd, dd_fs

lv1_y, lv1_y_fs, lv1_a, lv1_a_fs, lv1_d, lv1_d_fs = bank_level(x, x_fs)
lv2_y, lv2_y_fs, lv2_a, lv2_a_fs, lv2_d, lv2_d_fs = bank_level(lv1_a, lv1_a_fs, wavelet_="db2")
```

- **Аргументы.** Каждый вход — два аргумента: значение и его частота (`x`, `x_fs`), у коэффициентов — сведения (`c`, `c_meta`). Параметры блока — именованные аргументы со значениями по умолчанию из определения. Функция возвращает выходы в том же виде, парами.
- **Тело функции** считает всё из аргументов, как живой скрипт: одна функция годится и для `bank_level()`, и для `bank_level(wavelet=db2)`. Вложенные блоки — вызовы своих функций; функция вызываемого блока стоит в скрипте раньше.
- **Внутренние щупы.** Если в графе есть щупы внутри вызовов (`probe lv2/h0` или щуп в определении), функция получает необязательный словарь `trace` и кладёт в него эти значения под именами `вызов/узел`; после вызова скрипт достаёт их (`lv2_h0 = trace["lv2/h0"]`), и сверка проверяет их, как остальные щупы. Если таких щупов нет, словаря тоже нет.
- **Тетрадь** держит функции блоков в одной ячейке с остальными функциями, а каждый вызов — отдельная ячейка.
- **Ограничения.** Функция пишется по первому вызову, поэтому у всех вызовов порты должны быть одного типа. Граф, где выход вызова через другие узлы приходит на его же вход, функцией не записать — команда сообщает об этом.

### Тетрадь Jupyter

```bash
signals python examples/first_steps.sig -o first_steps.ipynb
```

С путём `.ipynb` команда пишет тетрадь Jupyter вместо скрипта. Код в ней тот же, что в скрипте, по ячейке на узел. Над каждой ячейкой — название блока и что он делает, после каждого щупа-сигнала — его график. Блок `listen` в тетради становится проигрывателем `IPython.display.Audio`. Последняя ячейка сверяет числа с программой и падает на `assert`, если хоть одна строка не сошлась. Тетрадь ищет `.npz` и входные файлы в текущей папке, поэтому запускайте Jupyter из папки тетради. Нужны ещё matplotlib и IPython; версии, на которых тетради проверяются в CI, — в `tools/requirements-bridge.txt`.

### Сверка

В конце скрипт сравнивает каждый щуп, каждое поле каждого отчёта и вход каждого узла с побочным действием (`wav_out`, `export`, `listen`) с тем, что посчитала программа, печатает таблицу «что — макс. |Python − Signals| — допуск — откуда допуск» и выходит с кодом 1 при любом ✗. Число совпадает, если `max|a − b| ≤ tol · max(1, max|b|)`; строки сравниваются точно, путь к файлу — по имени файла.

По умолчанию `tol` = 10⁻¹². У нескольких блоков библиотечный вызов даёт те же числа только грубее, и скрипт всё равно вызывает его, чтобы его можно было читать:

| Блок | Допуск | Вызов |
|---|---|---|
| `iir` | 10⁻⁸ | `scipy.signal.iirfilter`, `sosfilt`, `sosfiltfilt` |
| `remez` | 10⁻⁸ | `scipy.signal.remez` |
| `firls` | 10⁻¹⁰ | `scipy.signal.firls` |
| `lms` | 10⁻¹⁰ | своя функция |
| `sst_band`, `sst_ridge` | 10⁻¹⁰ | своя функция |
| `cepstrum` | 10⁻⁹ | своя функция на `numpy.fft` |
| `time_stretch`, `pitch_shift` | 10⁻⁹ | своя функция на `numpy.fft` |
| `inst_freq` | 10⁻⁷ | `scipy.signal.hilbert` |

Фазовый вокодер `time_stretch` и `pitch_shift` складывает фазу всех кадров, поэтому последний бит БПФ растёт с длиной звука. А он у numpy зависит от сборки: колёса для Apple Silicon считают БПФ с совмещённым умножением-сложением (FMA), Signals — без него. На 10 секундах звука это 5·10⁻¹², допуск 10⁻⁹ рассчитан примерно на полчаса.

У `inst_freq` то же по другой причине: разность соседних фаз берётся после развёртки, а развёрнутая фаза растёт с длиной сигнала, и её последний разряд — тоже. На 10 секундах звука 44,1 кГц это 2,6·10⁻⁸ герца, допуск 10⁻⁷ рассчитан на несколько часов.

Щуп получает самый слабый допуск среди блоков выше него по графу; таблица сверки называет блок, который его задал.

Поля отчёта в децибелах (`snr_db`, `thd_db` и т. п.) сравниваются после ограничения пределом ±200 дБ: выше этого лежит отношение к шуму округления double, которое не повторяет ни одна другая реализация. Так `check` совершенного восстановления совпадает, хотя его SNR около 300 дБ.

Вейвлет идёт в pywt по имени, если фильтры pywt совпадают с фильтрами Signals до 10⁻¹⁵. Двенадцать симлетов (`sym2`–`sym10`, `sym12`, `sym13`, `sym17`) Signals строит сам, и их таблица у pywt отличается до 4·10⁻¹²; для них скрипт строит `pywt.Wavelet("sym8", filter_bank=…)` из чисел Signals, и графы с ними остаются на 10⁻¹².

Блоки, которые выбирают по сравнению (пики, онсеты, правило `sure`, лучший базис `wpt`), считают решающую величину теми же операциями и в том же порядке, что программа. Если у вашего графа две величины окажутся точно равны, выбор может разойтись — сверка честно покажет ✗.

Поле `bytes` у `export` и `export_report` в CSV и JSON сверяется с допуском 10⁻²: числа в тексте пишутся по 17 значащих цифр, и число, которое сходится лишь до допуска, может записаться на знак длиннее или короче.

Скрипт ищет `.npz` и входные файлы рядом с собой, поэтому его можно запускать из любой папки и переносить вместе с данными.

## Предпросмотр в VS Code

Расширение VS Code из `editors/vscode` показывает граф рядом с файлом: команда «Signals: Preview» (кнопка в заголовке редактора) запускает `signals run --watch --json` и при каждом сохранении рисует графики щупов-сигналов, полосы коэффициентов, отчёты и состояние узлов. Ошибка в графе попадает в «Проблемы» на своей строке. Нужна Signals 0.9.0 или новее; путь к программе задаёт настройка `signals.path`. Подсказка над блоком показывает его Python-форму.

## Знак деталей

Signals считает детальные коэффициенты с обратным знаком относительно pywt. Так принято в книге Стрэнга и Нгуена. Вне программы всё в знаке pywt:

- при записи `dwt` и `swt` знак деталей меняется, в файл пишется `detail_sign = "pywt"`; пакеты `wpt` программа и так считает в знаке pywt;
- при чтении файл без `detail_sign` или с `"pywt"` переводится в знак Signals, `"signals"` читается как есть;
- у лифтинга и `dtcwt` аналога в pywt нет: их полосы пишутся как есть, с `detail_sign = "signals"`.

Поэтому `cD1` в файле противоположен тому, что показывает «Разложение». На восстановленный сигнал знак не влияет.
