## Приложение. Настройки и файлы {#settings}

Signals хранит на диске немного: настройки терминала и редактора в `terminal.toml`, сеанс (тема, последняя вкладка, недавние файлы и графы) в `session.toml` и папку со своими фильтрами. Кэша и журналов у программы нет; всё остальное, что она пишет, пишется туда, куда укажете вы. Ниже перечислено, где лежат эти файлы, какие в них ключи и как их менять.

### Папка настроек {#settings-dir}

Папка выбирается при запуске по первому подходящему правилу:

| Условие | Папка |
|---|---|
| задана переменная `XDG_CONFIG_HOME` (на любой системе) | `$XDG_CONFIG_HOME/signals/` |
| Windows и задана `APPDATA` | `%APPDATA%\signals\` |
| иначе | `~/.config/signals/` (`$HOME/.config/signals/`) |

На macOS это тоже `~/.config/signals/`, а не `~/Library/Application Support`. Папку и файлы программа создаёт сама при первом сохранении. Если не задан даже `HOME`, настройки лягут в `./.config/signals/` текущей папки, а фильтры в `./signals-filters/`.

В папке три объекта:

| Путь | Что это |
|---|---|
| `terminal.toml` | цвет, глифы, язык, редактор и отметка о проверке терминала |
| `session.toml` | сеанс: тема, последняя вкладка, недавние звуковые файлы и графы |
| `filters/*.flt` | «Мои фильтры»: свои банки и одиночные фильтры |

### Файл terminal.toml {#settings-terminal}

Обычный TOML. Пример:

```
checked = true
color = "truecolor"
glyphs = "unicode"
language = "ru"
editor = "code -w"
```

| Ключ | Значения | Если ключа нет | Кто записывает |
|---|---|---|---|
| `checked` | `true`, `false` | `false`: при запуске откроется проверка терминала | проверка терминала (`Esc` при первом запуске или `s`) |
| `color` | `none`, `ansi16`, `palette256`, `truecolor` | глубина цвета определяется по окружению | проверка терминала, клавиша `s` |
| `glyphs` | `unicode`, `ascii` | глифы определяются по локали | проверка терминала, клавиша `s` |
| `language` | `ru`, `en` (понимаются и `en_US`, `english`, `русский`) | русский | команды палитры «Язык: …» |
| `editor` | команда редактора, например `code -w` | `VISUAL`, затем `EDITOR`, затем системный | команда палитры «Редактор для исходников…» |

Программа переписывает файл целиком из этих пяти ключей, поэтому посторонние ключи при следующем сохранении пропадут. Если файл не разбирается как TOML, программа работает с настройками по умолчанию и снова показывает проверку терминала.

Проверку терминала можно открыть в любой момент: палитра `:`, команда «Проверка терминала». Цифры `1`–`4` пробуют глубину цвета, `u` и `a` глифы, `s` сохраняет выбор в `terminal.toml`.

### Редактор для исходников {#settings-editor}

На вкладке «Теория ▸ Под капотом» клавиша `o` показывает исходник блока внутри программы, а `e` или кнопка «открыть в редакторе» открывают тот же файл во внешнем редакторе. Для этого рядом должен быть репозиторий с исходниками. Редактор выбирается так:

1. ключ `editor` в `terminal.toml`, если он не пустой;
2. переменная `VISUAL`;
3. переменная `EDITOR`;
4. системная программа: `open -t` на macOS, `xdg-open` на Linux, `notepad` на Windows.

Задать редактор проще всего из программы: палитра `:`, команда «Редактор для исходников…», ввести команду и `Enter`. Стёртое поле и `Enter` убирают настройку, и снова действуют `VISUAL`, `EDITOR` и системная программа. Команда делится по пробелам, путь к файлу добавляется последним словом; кавычки внутри команды не поддерживаются.

| Редактор | Команда |
|---|---|
| VS Code | `code -w` |
| Cursor | `cursor -w` |
| Sublime Text | `subl -w` |
| Zed | `zed -w` |
| Neovim, Vim | `nvim`, `vim` |
| nano | `nano` |

Консольный редактор открывается в том же терминале: интерфейс Signals на это время уходит и возвращается, когда редактор закрыт. Если у VS Code нет команды `code` в `PATH`, установите её из VS Code (палитра ⇧⌘P, «Shell Command: Install 'code' command in PATH») или укажите полный путь без пробелов.

### Мои фильтры: папка filters {#settings-filters}

Каждый свой фильтр или банк хранится отдельным файлом `.flt` в папке `filters/`. Файлы появляются, когда вы сохраняете банк в «Конструкторе» или вводите `имя = коэффициенты` по `c` на вкладке «Фильтры». При запуске программа читает все `.flt` этой папки; файл с ошибкой пропускается, а причина появляется в журнале вкладки «Сигнал».

Банк:

```
name = "мой_банк"
kind = "bank"
h0_offset = 0
h0 = [0.48296291314469025, 0.836516303737469, 0.22414386804185735, -0.12940952255092145]
f0_offset = 0
f0 = [-0.12940952255092145, 0.22414386804185735, 0.836516303737469, 0.48296291314469025]
note = "Добеши 2, перепроверено"
```

Одиночный фильтр:

```
name = "h1"
kind = "filter"
h_offset = 0
h = [0.5, -0.5]
note = ""
```

| Ключ | Банк | Фильтр | Смысл |
|---|---|---|---|
| `name` | да | да | имя в списках; если нет, берётся имя файла |
| `kind` | `"bank"` (по умолчанию) | `"filter"` | что лежит в файле |
| `h0`, `f0` | обязательно | — | ФНЧ анализа и синтеза; ФВЧ строятся по ним |
| `h` | — | обязательно | коэффициенты фильтра |
| `h0_offset`, `f0_offset`, `h_offset` | можно | можно | индекс первого отвода, целое число, по умолчанию 0 |
| `note` | можно | можно | заметка, показывается рядом с именем |

Имя файла получается из имени фильтра: пробелы становятся `_`, знаки препинания убираются, буквы любого алфавита остаются. Если имя занято, к нему добавляется `-2`, `-3` и так далее. Файлы можно писать и править руками: после перезапуска программа их прочитает, а банк без полного восстановления не примет и скажет почему. Для VS Code есть расширение в `editors/vscode`, оно подсвечивает `.flt` и проверяет банк при наборе.

Свои банки работают везде, где выбирается вейвлет или фильтр: на вкладках, в блоках конвейера (`dwt(wavelet=мой_банк)`, `convolve(filter=мой_банк.h0)`) и в командной строке (`signals filter мой_банк`).

### Переменные окружения {#settings-env}

| Переменная | Что делает |
|---|---|
| `SIGNALS_LANG` | язык интерфейса и сообщений (`ru` или `en`); сильнее сохранённого языка, слабее ключа `--lang` |
| `XDG_CONFIG_HOME` | корень папки настроек на любой системе |
| `APPDATA` | корень папки настроек на Windows, если нет `XDG_CONFIG_HOME` |
| `HOME` | `~/.config/signals/` и `~` в путях, которые вводятся в программе |
| `VISUAL`, `EDITOR` | редактор для исходников, если не задан ключ `editor` |
| `NO_COLOR` | любое непустое значение выключает цвет, даже сохранённый в `terminal.toml` |
| `TERM` | `dumb` выключает цвет и Unicode; `…256color` даёт 256 цветов |
| `COLORTERM` | `truecolor` или `24bit` дают 24-битный цвет |
| `TERM_PROGRAM` | `Apple_Terminal` даёт 256 цветов |
| `WT_SESSION` | Windows Terminal: 24-битный цвет и Unicode |
| `LC_ALL`, `LC_CTYPE`, `LANG` | первая непустая решает, Unicode или ASCII: UTF-8 значит Unicode |

Язык выбирается в таком порядке: `--lang`, затем `SIGNALS_LANG`, затем `language` из `terminal.toml`, затем русский. Команды вне интерфейса (`signals run`, `signals filter` и другие) файл настроек не читают: для них действуют только `--lang` и `SIGNALS_LANG`.

### Что сохраняется, а что нет {#settings-session}

| Действие | Сохраняется |
|---|---|
| «Язык: русский» и «Язык: English (английский)» в палитре | да, ключ `language`; интерфейс перезапускается |
| `s` в проверке терминала | да, ключи `color`, `glyphs`, `checked` |
| «Редактор для исходников…» в палитре | да, ключ `editor` |
| сохранение банка в «Конструкторе», `c` на «Фильтрах» | да, файл в `filters/` |
| «Тема: светлая» и «Тема: тёмная» в палитре | да, ключ `theme` в `session.toml` |
| открытый звуковой файл, открытый или сохранённый граф | да, списки `audio` и `graphs` в `session.toml` |
| вкладка, на которой закрыли программу | да, ключ `tab` в `session.toml` |
| «Глифы: …», «Цвет: …» в палитре | нет, только до выхода |
| `--lang`, `--theme` в командной строке | нет, только этот запуск |

### Файл session.toml {#settings-session-file}

Сеанс программа пишет сама, руками его править не нужно. Пример:

```toml
theme = "light"
tab = 7
audio = ["/home/u/rec/take.flac", "/home/u/rec/test.wav"]
graphs = ["/home/u/sig/denoise.sig"]
```

| Ключ | Что значит |
|---|---|
| `theme` | `dark` или `light`, тема из палитры; `--theme` в командной строке сильнее и не сохраняется |
| `tab` | номер вкладки с нуля, на которой программу закрыли |
| `audio` | до 10 последних звуковых файлов, свежий первым; файл попадает сюда, когда он прочитан без ошибки |
| `graphs` | до 10 последних графов `.sig`, которые открывали или сохраняли в «Конвейере» |

`signals tui` без файла открывает первый существующий файл из `audio`, первый существующий граф из `graphs` и вкладку `tab`. С файлом в командной строке открывается он и вкладка «Сигнал», а граф и вкладка не восстанавливаются. Команда палитры «Открыть недавний…» показывает оба списка (пропавшие файлы в нём не видны), «Забыть недавние файлы» очищает их. Испорченный `session.toml` не мешает запуску: программа начинает с пустого сеанса и перезапишет файл.

### Файлы рядом с графами {#settings-outputs}

Блоки `export`, `export_report` и `wav_out` пишут файлы туда, куда указывает их параметр `path`. Относительный путь считается так:

| Как запущен граф | Относительно чего |
|---|---|
| `signals run граф.sig` | папки файла `.sig` |
| «Конвейер», граф ещё не сохранён | папки, из которой запущен `signals tui` |
| «Конвейер», граф открыт или сохранён | папки файла `.sig` |

При сохранении графа в другую папку программа пересчитывает относительные пути, чтобы они вели в те же места. Запись идёт через временный файл `.имя.XXXXXXXXXXXXXXXX.partial` рядом с целевым, который затем переименовывается; если запуск прервали, такой файл может остаться, его можно удалить. Ключи `--probe-dir` и `-o` команды `signals run` и `--bands-dir` команды `signals dwt` считаются от текущей папки.

### Как всё сбросить {#settings-reset}

Удалите `terminal.toml`: при следующем запуске откроется проверка терминала, язык станет русским, редактор вернётся к `VISUAL`, `EDITOR` и системной программе. Удалите `session.toml`, чтобы забыть тему, вкладку и недавние файлы. Удалите папку `filters/` или отдельные `.flt`, чтобы убрать свои фильтры. Больше программа ничего не хранит.
