## Приложение. Формат конвейера .sig {#sig-format}

Файл `.sig` — текстовое описание графа «Конвейера»: какие блоки взять, с какими параметрами и как их соединить. Его пишет и читает вкладка «Конвейер», его выполняют `signals run` и рисует `signals graph`, а править его руками можно в любом текстовом редакторе (для VS Code есть расширение в папке `editors/vscode`: подсветка, подсказки и дополнение).

Небольшой пример — банк Хаара на одном уровне:

```
pipeline "haar_bank" v2

# сигнал из восьми отсчётов, как на «Объяснении»
node x   = samples(values="4 6 10 12 8 6 5 5", rate=8)
node h0  = convolve(filter=haar.h0, method=direct)
node h1  = convolve(filter=haar.h1, method=direct)
node a   = downsample(m=2, anti_alias=no, phase=1)
node d   = downsample(m=2, anti_alias=no, phase=1)
node ua  = upsample(m=2, anti_image=no)
node ud  = upsample(m=2, anti_image=no)
node f0  = convolve(filter=haar.f0, method=direct)
node f1  = convolve(filter=haar.f1, method=direct)
node sum = add()
node pr  = check(kind=pr, tol=1e-12, delay=auto)

x -> h0 -> a -> ua -> f0 -> sum.a
x -> h1 -> d -> ud -> f1 -> sum.b
x -> pr.ref
sum -> pr.in
probe a as "a"
probe d as "d"
probe sum as "x̂"
```

### Строки файла {#sig-lines}

Одна инструкция — одна строка. Порядок строк не важен: провод можно написать раньше узлов, которые он соединяет. Пустые строки и отступы допускаются.

- `pipeline "имя" v2` — заголовок: имя графа в кавычках и версия формата. Текущая версия — `v2`. Файлы `v1` программа читает сама и переводит в `v2` при открытии (раздел «Версии формата»).
- `node id = блок(параметр=значение, …)` — узел. Имя узла `id` состоит из латинских букв, цифр и подчёркивания и начинается с буквы или `_`; имена не повторяются. Параметры перечисляются через запятую в любом порядке; неуказанные берут значения по умолчанию, поэтому `add()` и просто `add` равноправны. Внутри скобок строку можно переносить.
- `node id = блок(…) bypass` — узел обходится: вход идёт прямо на выход, блок не считается. Так можно обойти только блок, у которого вход и выход одного типа.
- `a -> b -> c` — цепочка проводов: выход `a` на вход `b`, выход `b` на вход `c`. Порт указывается через точку: `x -> pr.ref`, `sum -> pr.in`, `lms.e -> out`. В середине цепочки порт не пишется — такую цепочку разбивают на две строки.
- `probe узел as "имя"` или `probe узел.порт as "имя"` — щуп: этот выход видно в панели «Щуп». Имя необязательно, но не должно повторяться.
- `#` — комментарий до конца строки (кроме `#` внутри кавычек). Комментарии переживают сохранение из «Конвейера»: строки комментариев над узлом, проводом или щупом остаются над ним, комментарий в конце строки — в конце строки, пустые строки между группами узлов тоже сохраняются. Комментарий внутри скобок многострочного узла переезжает на строку над узлом. Удалённый узел уносит свои комментарии; если удалить первый провод цепочки, её комментарий переходит к оставшемуся проводу той же строки.

### Порты {#sig-ports}

У каждого блока есть входы и выходы определённого типа (их список — в справочнике блоков и в инспекторе):

- `signal` — сигнал: один или несколько каналов и частота дискретизации;
- `coeffs` — вейвлет-коэффициенты (результат `dwt`, `swt`, `wpt`, `dtcwt`, лифтинга);
- `filter` — банк фильтров;
- `scalar` — одно число;
- `report` — отчёт: поля и признак «прошла ли проверка».

Порт можно не писать, если выбор однозначен: у узла один вход или один обязательный вход, у источника один выход. Если входов или выходов несколько, программа попросит указать порт и перечислит варианты. Необязательный вход, к которому ничего не подключено, получает пустой сигнал: так, например, `multiply` без входа `b` умножает на константу, а `spectral_subtract` без входа `noise` берёт шум из начала сигнала.

У выхода `coeffs` есть полосы: `dwt.a` — приближение последнего уровня, `dwt.d1` … `dwt.dJ` — детали уровней 1…J. Полосу можно подать на вход сигнала или поставить на неё щуп. Номер полосы заранее проверяется для `dwt` с заданным числом уровней; у пакетов `wpt` полосы называются путями узлов (`aa`, `ad`, …) и выбираются в `mra.component` и `band_edit.enabled`.

### Значения параметров {#sig-values}

- **Числа:** `440`, `0.25`, `-3`, `1e-12` — с точкой, а не с запятой.
- **Выражения вместо чисел:** числовой параметр можно задать выражением в кавычках: `db="20*log10(2)"`, `m="2^3"`, `cutoff="fs/4"` не сработает (имён нет), а `cutoff="44100/4"` — да. Работают `+ - * / ^`, скобки, `abs min max sqrt log10` и `pi`. В файле остаётся текст выражения, а в расчёт идёт его значение; у целых параметров значение должно быть целым.
- **Длительности и отсчёты:** часть параметров принимает число отсчётов или секунды с суффиксом `s` — `cut.begin`/`end`, `delay.samples`, `pad.before`/`after`, `fade.fade_in`/`fade_out`, `sample_hold.hold`, `impulse_train.period`/`offset` и другие (инспектор показывает, где это можно): `begin=4410`, `begin=0.1s`. Остальные целые параметры, например `shift.samples`, — только в отсчётах.
- **Уровни:** одно число или диапазон `1..4`.
- **Выбор из списка:** слово из перечня этого параметра: `ext=symmetric`, `anti_alias=no`, `kind=pr`.
- **Фильтр:** `банк.роль`, где роль — `h0`, `h1`, `f0` или `f1`: `haar.h0`, `db4.f1`, `sym8.h1`. Свой банк из «Моих фильтров» пишется по своему имени (`мой_банк.h0`), а свой одиночный фильтр — по имени целиком.
- **Вейвлет:** имя из библиотеки (`db2`, `sym8`, `bior2.2`, …), свой банк по имени или `auto` — взять вейвлет из пришедших коэффициентов.
- **Строки в кавычках:** `path="../audio/test.wav"`, `values="4 6 10 12"`. Кавычки нужны, если в значении есть пробел, запятая, скобка, `#` или `=`. Внутри кавычек пишут `\"` и `\\`.
- **Пути:** относительный путь отсчитывается от папки файла `.sig`.

Значение проверяется сразу: число вне диапазона, неизвестный вариант выбора или неразборчивое число дают ошибку с именем узла и параметра.

### Проверка графа {#sig-checks}

Кроме `check`, условия на результаты прогона задаёт блок `assert`. На его входы `a`, `b`, `c`, `d` подаются отчёты других блоков, а параметр `expr` — выражение над их полями:

```
node c = check(kind=snr, tol=0)
node g = assert(expr="a.snr_db >= 30 && a.passed")
c -> g.a
```

Имена полей — как в отчёте блока: `a.max_abs`, `a.snr_db`, `b.lag_samples`; `a.passed` — 1, если проверка прошла. Ложное выражение помечает узел как проваленный и, как у `check`, даёт код выхода 3 у `signals run`. Опечатка в имени поля — ошибка узла с подсказкой ближайшего имени.


Перед запуском граф проверяется целиком, и каждая ошибка указывает строку:

- неизвестный блок или узел — с подсказкой «может быть …», если есть похожее имя;
- у входа два провода или обязательный вход не подключён;
- тип выхода не подходит ко входу (например, `coeffs` в `signal`); программа подскажет вставить `idwt` или `dwt`;
- цикл: граф идёт от источников к выходам без петель;
- полоса `dJ` за пределами числа уровней;
- одно имя у двух щупов.

### Командная строка {#sig-cli}

- `signals run граф.sig` — выполнить граф и напечатать этапы, время и память каждого узла и отчёты проверок.
  - `--set узел.параметр=значение` — подменить параметр, можно несколько раз: `--set x.path=other.wav --set dwt.levels=5`;
  - `-o out.wav` — куда записать первый `wav_out`;
  - `--probe-dir папка` — сохранить щупы: сигналы в WAV, остальное в JSON;
  - `--values N` — печатать первые N отсчётов каждого щупа-сигнала (`0` — не печатать); без ключа печатаются все отсчёты сигналов не длиннее 64;
  - `--watch` — после запуска следить за файлом графа и входными файлами (блок `wav`) и запускать заново при каждом изменении; выходные файлы не отслеживаются, так что запуск не перезапускает сам себя. `Ctrl+C` завершает с кодом 0; с `--json` каждый прогон — одна строка JSON на stdout (NDJSON), ошибка графа — строка `{"error": {"file", "line", "message"}}`, а служебные строки уходят в stderr;
  - `--report отчёт.md` — отчёт Markdown: граф, таблица узлов, графики щупов во времени и спектр (SVG и CSV в папке `отчёт_files`), поля отчётов;
  - `--json` — отчёт о запуске в JSON.
  
  Код выхода `0` — всё прошло, `3` — какая-то проверка `check` или `assert` не прошла, `1` — ошибка в файле или при счёте, `130` — запуск прерван Ctrl+C.
- `signals sweep граф.sig --vary узел.параметр=значения --measure показатель` — серия прогонов: граф считается по разу на каждое значение параметра, и для каждого прогона печатается строка показателей.
  - Значения: `0:1:0.1` (от, до, шаг), `1:100@5` (5 точек поровну), `1:100@5log` (5 точек в логарифмическом масштабе), `haar,db4,sym8` (список, подходит и для выбора). Больше 1000 значений не принимается.
  - Показатель: поле отчёта `узел.поле` (например `chk.snr_db`) или мера выхода узла `узел:rms`, `узел:peak`, `узел:energy`, `узел:mean`, `узел:length`. `--measure` можно повторить.
  - `--set` как у `run`; `--csv таблица.csv` и `--svg график.svg` сохраняют результат, `--json` печатает его в JSON.
  - Блоки, которые пишут файлы (`wav_out`, `export`), в серии не запускаются, если их не измеряют, поэтому серия не затирает результаты обычного запуска. Ошибка одного прогона не останавливает серию: строка остаётся с пустыми показателями и текстом ошибки.

  Например, какая вейвлета лучше чистит шум в `examples/denoise.sig`:

  ```
  $ signals sweep examples/denoise.sig --vary "dwt.wavelet=haar,db4,sym8,coif3" --measure chk.snr_db
  серия: dwt.wavelet, прогонов 4
    dwt.wavelet  chk.snr_db
    haar         27.9459
    db4          46.3981
    sym8         51.2006
    coif3        49.7729
  ```

  В «Конвейере» то же делает `S` на выбранном узле: программа спрашивает параметр, значения (подставляет диапазон вокруг текущего) и показатель, а результат показывает щуп «серия» графиком или таблицей (`v`). `Esc` прерывает серию.
- `signals graph граф.sig` — нарисовать граф текстом (`--ascii` — только ASCII).
- `signals blocks` — список блоков; `--markdown` — справочник `docs/user/blocks.md`; `--json` — описание блоков для редакторов.
- `signals explain блок` — один блок подробно: что делает, порты, каждый параметр со значением по умолчанию, диапазоном и пояснением, смысл каждого значения выбора и карточка теории. Опечатка в имени подсказывает ближайший блок.

### Версии формата {#sig-versions}

Номер в заголовке — версия формата, а не программы. Текущая версия — `v2`. Signals читает файлы всех прошлых версий и пишет только текущую.

- **Открытие старого файла.** «Конвейер», `signals run`, `watch`, `sweep`, `graph`, `python`, задания курса и работы учеников переводят старый файл в памяти. Файл на диске не меняется. «Конвейер» пишет в строке уведомлений «граф v1 переведён в v2…», а список изменений открывает команда палитры «Что изменилось при переводе». `Ctrl+S` сохраняет граф уже в `v2`. CLI печатает в stderr одну строку о переводе, а в `--json` и в NDJSON у `watch` появляются поля `migrated_from` и `migration_notes`.
- **Перевод файлов на диске** — `signals migrate`:
  - `signals migrate ПУТЬ…` — файлы и папки (папки обходятся вглубь). Печатает версию каждого файла и что изменится, ничего не меняя.
  - `--write` — переписать старые файлы. Рядом остаётся копия `имя.v1.sig`; `--no-backup` её не делает.
  - `--check` — код 1, если есть файл в старом формате: так CI проверяет, что в репозитории всё переведено.
  
  В папке курса команда переводит и `task.toml`: имена блоков, параметров и полей (копия — `task.v1.toml`). Файл, который не разбирается, называется с номером строки, остальные файлы переводятся. Копии `*.v1.sig` и `*.v1.toml` команда пропускает, и в своём курсе они не считаются заданиями.
- **Что меняет перевод `v1` → `v2`.** В `v2` знак `$` начинает подстановку переменной, поэтому буквальный `$` в значении параметра записывается как `$$`. Перевод делает это сам: `path="a$b.wav"` становится `path="a$$b.wav"`, а программа по-прежнему читает файл `a$b.wav`. Ещё перевод заменяет старые имена параметров, вариантов и полей отчётов на новые — их список в разделе «Что изменилось в v2».
- **Кодировка и концы строк.** Файл с меткой UTF-8 в начале (BOM) и с концами строк Windows (CRLF) читается как обычный. При записи программа пишет UTF-8 без BOM и концы строк LF.
- **Файл новее программы.** Файл версии `v3` эта программа не откроет и попросит обновить Signals.

Правило на будущее: любое изменение формата — новая версия и шаг перевода. Старые версии читаются всегда, а образцы каждой лежат в тестах (`tests/fixtures/sig/v1`): перевод обязан давать тот же текст и те же числа.

### Что изменилось в v2 {#sig-v2-changes}

Перед тем как зафиксировать формат, имена блоков, параметров, вариантов, портов и полей отчётов сверены по одному правилу: одно значение — одно имя во всех блоках. Переименовано только то, где одно и то же называлось по-разному или имя вводило в заблуждение. Файлы `v1` со старыми именами переводятся сами: в узлах, в `assert(expr=…)`, в `task.toml` курсов; `--set` и `--measure` со старым именем называют новое.

| Блок | Было | Стало | Почему |
|---|---|---|---|
| `speed` | `rate` | `factor` | `rate` везде — частота дискретизации, а здесь — во сколько раз быстрее |
| `time_stretch` | `rate` | `factor` | `rate` везде — частота дискретизации, а здесь — во сколько раз быстрее |
| `lms` | `taps` | `numtaps` | число отводов везде `numtaps`; `taps` у `fir_taps` — сами отводы |
| `pitch` | `fmin` | `min_hz` | границы частот в герцах везде `min_hz` и `max_hz` |
| `pitch` | `fmax` | `max_hz` | границы частот в герцах везде `min_hz` и `max_hz` |
| `sst_band` | `lo` | `min_hz` | границы частот в герцах везде `min_hz` и `max_hz` |
| `sst_band` | `hi` | `max_hz` | границы частот в герцах везде `min_hz` и `max_hz` |
| `sst_ridge` | `lo` | `min_hz` | границы частот в герцах везде `min_hz` и `max_hz` |
| `sst_ridge` | `hi` | `max_hz` | границы частот в герцах везде `min_hz` и `max_hz` |
| `loudness` | `window` | `frame` | длина кадра анализа с шагом `hop` везде `frame` |
| `spectral_subtract` | `n` | `frame` | длина кадра анализа с шагом `hop` везде `frame` |
| `onsets` | `n` | `frame` | длина кадра анализа с шагом `hop` везде `frame` |
| `time_stretch` | `n_fft` | `frame` | длина кадра анализа с шагом `hop` везде `frame` |
| `pitch_shift` | `n_fft` | `frame` | длина кадра анализа с шагом `hop` везде `frame` |
| `savgol` | `window` | `length` | длина окна сглаживания везде `length`; `window` у `fir` — вид окна |

| `impulse_train` | `offset` | `begin` | положение начала везде `begin`; `offset` — прибавляемая постоянная |
| `wav_out` | `dither=tpdf` | `dither=yes` | тот же выбор у `quantize` — `yes` или `no` |
| `wav_out` | `dither=none` | `dither=no` | тот же выбор у `quantize` — `yes` или `no` |
| `loudness` | поле `windows` | поле `frames` | число кадров анализа везде `frames`; `assert` и `--measure` переводятся вместе с графом |

### Где смотреть блоки {#sig-blocks}

Полный список блоков с портами, параметрами, их смыслом и значениями по умолчанию — в `docs/user/blocks.md`. В программе: `a` в «Конвейере» открывает список блоков с описанием, инспектор объясняет каждый параметр и значение, `F1` на узле открывает карточку блока, `O` — готовые примеры.
