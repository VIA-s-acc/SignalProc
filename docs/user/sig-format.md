## Приложение. Формат конвейера .sig {#sig-format}

Файл `.sig` — текстовое описание графа «Конвейера»: какие блоки взять, с какими параметрами и как их соединить. Его пишет и читает вкладка «Конвейер», его выполняют `signals run` и рисует `signals graph`, а править его руками можно в любом текстовом редакторе (для VS Code есть расширение в папке `editors/vscode`: подсветка, подсказки и дополнение).

Небольшой пример — банк Хаара на одном уровне:

```
pipeline "haar_bank" v1

# сигнал из восьми отсчётов, как на «Объяснении»
node x   = samples(values="4 6 10 12 8 6 5 5", rate=8)
node h0  = convolve(filter=haar.h0, method=direct)
node h1  = convolve(filter=haar.h1, method=direct)
node a   = downsample(m=2, anti_alias=no, phase=1)
node d   = downsample(m=2, anti_alias=no, phase=1)
node ua  = upsample(m=2, anti_image=no)
node ud  = upsample(m=2, anti_image=no)
node f0  = convolve(filter=haar.f0, method=direct)
node f1  = convolve(filter=haar.f1, method=direct)
node sum = add()
node pr  = check(kind=pr, tol=1e-12, delay=auto)

x -> h0 -> a -> ua -> f0 -> sum.a
x -> h1 -> d -> ud -> f1 -> sum.b
x -> pr.ref
sum -> pr.in
probe a as "a"
probe d as "d"
probe sum as "x̂"
```

### Строки файла {#sig-lines}

Одна инструкция — одна строка. Порядок строк не важен: провод можно написать раньше узлов, которые он соединяет. Пустые строки и отступы допускаются.

- `pipeline "имя" v1` — заголовок: имя графа в кавычках и версия формата. Сейчас есть только `v1`.
- `node id = блок(параметр=значение, …)` — узел. Имя узла `id` состоит из латинских букв, цифр и подчёркивания и начинается с буквы или `_`; имена не повторяются. Параметры перечисляются через запятую в любом порядке; неуказанные берут значения по умолчанию, поэтому `add()` и просто `add` равноправны. Внутри скобок строку можно переносить.
- `node id = блок(…) bypass` — узел обходится: вход идёт прямо на выход, блок не считается. Так можно обойти только блок, у которого вход и выход одного типа.
- `a -> b -> c` — цепочка проводов: выход `a` на вход `b`, выход `b` на вход `c`. Порт указывается через точку: `x -> pr.ref`, `sum -> pr.in`, `lms.e -> out`. В середине цепочки порт не пишется — такую цепочку разбивают на две строки.
- `probe узел as "имя"` или `probe узел.порт as "имя"` — щуп: этот выход видно в панели «Щуп». Имя необязательно, но не должно повторяться.
- `#` — комментарий до конца строки (кроме `#` внутри кавычек).

### Порты {#sig-ports}

У каждого блока есть входы и выходы определённого типа (их список — в справочнике блоков и в инспекторе):

- `signal` — сигнал: один или несколько каналов и частота дискретизации;
- `coeffs` — вейвлет-коэффициенты (результат `dwt`, `swt`, `wpt`, лифтинга);
- `filter` — банк фильтров;
- `scalar` — одно число;
- `report` — отчёт: поля и признак «прошла ли проверка».

Порт можно не писать, если выбор однозначен: у узла один вход или один обязательный вход, у источника один выход. Если входов или выходов несколько, программа попросит указать порт и перечислит варианты. Необязательный вход, к которому ничего не подключено, получает пустой сигнал: так, например, `multiply` без входа `b` умножает на константу, а `spectral_subtract` без входа `noise` берёт шум из начала сигнала.

У выхода `coeffs` есть полосы: `dwt.a` — приближение последнего уровня, `dwt.d1` … `dwt.dJ` — детали уровней 1…J. Полосу можно подать на вход сигнала или поставить на неё щуп. Номер полосы заранее проверяется для `dwt` с заданным числом уровней; у пакетов `wpt` полосы называются путями узлов (`aa`, `ad`, …) и выбираются в `mra.component` и `band_edit.enabled`.

### Значения параметров {#sig-values}

- **Числа:** `440`, `0.25`, `-3`, `1e-12` — с точкой, а не с запятой.
- **Длительности и отсчёты:** часть параметров принимает число отсчётов или секунды с суффиксом `s` — `cut.begin`/`end`, `delay.samples`, `pad.before`/`after`, `fade.fade_in`/`fade_out`, `sample_hold.hold`, `impulse_train.period`/`offset` и другие (инспектор показывает, где это можно): `begin=4410`, `begin=0.1s`. Остальные целые параметры, например `shift.samples`, — только в отсчётах.
- **Уровни:** одно число или диапазон `1..4`.
- **Выбор из списка:** слово из перечня этого параметра: `ext=symmetric`, `anti_alias=no`, `kind=pr`.
- **Фильтр:** `банк.роль`, где роль — `h0`, `h1`, `f0` или `f1`: `haar.h0`, `db4.f1`, `sym8.h1`. Свой банк из «Моих фильтров» пишется по своему имени (`мой_банк.h0`), а свой одиночный фильтр — по имени целиком.
- **Вейвлет:** имя из библиотеки (`db2`, `sym8`, `bior2.2`, …), свой банк по имени или `auto` — взять вейвлет из пришедших коэффициентов.
- **Строки в кавычках:** `path="../audio/test.wav"`, `values="4 6 10 12"`. Кавычки нужны, если в значении есть пробел, запятая, скобка, `#` или `=`. Внутри кавычек пишут `\"` и `\\`.
- **Пути:** относительный путь отсчитывается от папки файла `.sig`.

Значение проверяется сразу: число вне диапазона, неизвестный вариант выбора или неразборчивое число дают ошибку с именем узла и параметра.

### Проверка графа {#sig-checks}

Перед запуском граф проверяется целиком, и каждая ошибка указывает строку:

- неизвестный блок или узел — с подсказкой «может быть …», если есть похожее имя;
- у входа два провода или обязательный вход не подключён;
- тип выхода не подходит ко входу (например, `coeffs` в `signal`); программа подскажет вставить `idwt` или `dwt`;
- цикл: граф идёт от источников к выходам без петель;
- полоса `dJ` за пределами числа уровней;
- одно имя у двух щупов.

### Командная строка {#sig-cli}

- `signals run граф.sig` — выполнить граф и напечатать этапы, время и память каждого узла и отчёты проверок.
  - `--set узел.параметр=значение` — подменить параметр, можно несколько раз: `--set x.path=other.wav --set dwt.levels=5`;
  - `-o out.wav` — куда записать первый `wav_out`;
  - `--probe-dir папка` — сохранить щупы: сигналы в WAV, остальное в JSON;
  - `--json` — отчёт о запуске в JSON.
  
  Код выхода `0` — всё прошло, `3` — какая-то проверка `check` не прошла, `1` — ошибка в файле или при счёте, `130` — запуск прерван Ctrl+C.
- `signals graph граф.sig` — нарисовать граф текстом (`--ascii` — только ASCII).
- `signals blocks` — список блоков; `--markdown` — справочник `docs/user/blocks.md`; `--json` — описание блоков для редакторов.

### Где смотреть блоки {#sig-blocks}

Полный список блоков с портами, параметрами, их смыслом и значениями по умолчанию — в `docs/user/blocks.md`. В программе: `a` в «Конвейере» открывает список блоков с описанием, инспектор объясняет каждый параметр и значение, `F1` на узле открывает карточку блока, `O` — готовые примеры.
