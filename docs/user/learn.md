## Приложение. Учебный путь {#learn}

Учебный путь — задания, которые программа проверяет сама. Одни задания просят собрать граф: банк Хаара, свёртку, шумоподавитель. Другие — найти число: задержку банка, частоту наложения, число разбиений. Задания идут от свёртки к шумоподавлению и ссылаются на разделы этой книги. Порядок рекомендуется, но открыто всё.

### Задания в интерфейсе {#learn-tui}

Задания живут на вкладке «Теория ▸ Задания» (`9`, затем `]` до «Задания»).

- **Слева** — главы и задания. ✓ — решено, ◐ — решено после разбора, ● — текущее задание. Сверху счётчик решённых и номер варианта.
- **В центре** — условие с формулами и ссылками на разделы книги.
- **Ниже** — цели с отметками ✓ и ✗ и измеренными числами, рядом подсказки и разбор.

Клавиши:

| Клавиша | Что делает |
|---|---|
| `Enter` | «Начать»: задание становится текущим. Задание-граф открывает свою заготовку в «Конвейере» как обычный файл; работа сохраняется `Ctrl+S` и не пропадает между запусками |
| `F2` | проверить текущее задание с любой вкладки |
| `F3` | открыть следующую подсказку с любой вкладки |
| `a` | ввести ответ у задания-ответа; `Enter` проверяет его |
| `h`, `s` | подсказка и разбор; разбор до решения программа покажет только после подтверждения |
| `t` | раздел книги к заданию |
| `v` | номер варианта |
| `Tab`, `z` | панели и панель на весь экран |

Пока задание текущее, над строкой подсказок на всех вкладках видна его строка: номер, название, «цели 2/4» или «засчитано ✓», клавиши `F2` и `F3`. Щелчок по ней открывает задание. После каждого прогона рабочего графа в «Конвейере» цели пересчитываются сами. `Esc` отменяет долгую проверку.

У разделов книги, к которым есть задания, внизу строка «Задания:» со ссылками на них.

### Как проходить путь из командной строки {#learn-use}

Список глав и заданий с отметками решённых:

```
signals learn
```

Условие задания и подсказки, открытые до сих пор:

```
signals learn show 4.3
```

Задание-граф начинается с заготовки. Команда записывает её в `4.3.sig` в текущей папке и никогда не перезаписывает файл, если он уже есть:

```
signals learn start 4.3
```

Граф правится в «Конвейере» (`signals tui 4.3.sig`) или в любом редакторе. Проверка:

```
signals learn check 4.3 4.3.sig
```

У задания-ответа файла нет, ответ пишется в команде. Вектор — числа через пробел или запятую, каждое число может быть выражением: `sqrt(2)/2`, `1/3`, `2^-10`. В ответе-числе запятая служит десятичным знаком: `0,5`.

```
signals learn check 1.1 --answer "2 -3 0 7 1 -4"
```

Подсказки открываются по одной:

```
signals learn hint 4.3
```

Разбор после решения показывается сразу. До решения программа просит подтверждения `--yes` и отмечает задание как решённое с разбором:

```
signals learn solution 4.3 --yes
```

Код выхода `check`: 0 — засчитано, 3 — цели пока не выполнены, 1 — граф не найден, не собирается, в нём изменены закреплённые узлы или задание с ошибкой, 2 — неверный вызов.

### Как проверяется задание {#learn-check}

Проверка не верит узлам студента. Она сама прогоняет граф, ставит свои щупы на нужные выходы и считает измерения: ошибку восстановления, SNR, задержку, уровень тона, длину. По ним проверяются цели задания. Цели видны в условии; у каждой после проверки — ✓ или ✗ и измеренное значение.

Чтобы задание нельзя было «решить» подгонкой под один ответ, у проверки есть три защиты:

- **Скрытые входы.** Узел-источник `samples` из заготовки получает другие отсчёты — случайные целые от −9 до 9 той же длины, — и граф прогоняется ещё несколько раз. Засчитывается, только если цели выполнены на всех входах. Переписанный в `samples` готовый ответ на скрытых входах не совпадёт.
- **Закреплённые узлы.** Узлы, которые задание просит не менять, сверяются с заготовкой: тип и параметры должны остаться прежними. Значения источника при этом не важны.
- **Условия на устройство графа.** Например, «каждый путь от `x` к `sum` проходит через ↓2» или «блок `dwt` запрещён». Провод `x → sum` в обход банка такое условие не пропустит.

Проверка одного задания ограничена 30 секундами; слишком тяжёлый граф даст ошибку, а не зависание.

### Прогресс, варианты и отчёт {#learn-progress}

Прогресс лежит в `learn.toml` в папке настроек ({#settings-dir}): имя, номер варианта и по каждому заданию состояние, число попыток и подсказок, время решения и последний ответ. Решённый граф копируется в `learn/<номер>.sig` там же, а рабочий граф интерфейса лежит в `learn/work/v<вариант>/<номер>.sig`: у каждого варианта своя заготовка. Если файл прогресса повреждён, программа сохраняет его как `learn.toml.bak` и начинает заново, а не падает.

У каждого студента свой **вариант** — номер от 1 до 999. От него зависят числа в заданиях: сигнал, фильтр, частоты. Одно и то же задание с тем же вариантом даёт одинаковые числа на любой машине.

```
signals learn variant 17 --student "Анна Иванова"
```

Отчёт для преподавателя — Markdown со списком глав, решёнными заданиями, целями с числами, ответами и графами:

```
signals learn report -o report.md
```

В отчёте у каждого решённого задания записан вариант, на котором оно решено, поэтому преподаватель может проверить ответ той же командой: `signals learn check 4.4 --variant 17 --answer 2`. Ключи `--variant N` и `--progress FILE` есть у всех команд `signals learn`: первый меняет вариант на одну команду, второй берёт другой файл прогресса.

### Свой курс {#learn-course}

Курс — папка с главами, глава — папка с заданиями. Номера берутся из префиксов `NN-`: папка `04-haar/03-build-bank` — задание 4.3.

```
course.toml              title, title_en
04-haar/
  chapter.toml           title, title_en, theory = [разделы книги]
  03-build-bank/
    task.toml            машинная часть
    start.sig            заготовка (для заданий-графов)
    solution.sig         эталонное решение
    cheats/*.sig         обходы, которые обязаны провалиться
    ru.md, en.md         условие, цели, подсказки, разбор
```

`task.toml`:

```
kind = "graph"          # graph или answer
open = "pipeline"       # вкладка, которую откроет «Начать»
theory = ["haar-walkthrough"]
locked = ["x"]          # узлы, которые нельзя менять

[[param]]               # числа варианта
name = "x"
kind = "ints"           # int, ints, real, choice
count = 8
min = -9
max = 9

[input]                 # скрытые входы
node = "x"
hidden = 4

[[measure]]
name = "err"
kind = "max_error"
a = "sum"
b = "x"
delay = "auto"

[[goal]]
when = "err <= 1e-12"

[[goal]]
through = { from = "x", to = "sum", block = "downsample" }
```

Своим курсом пользуются через `--course папка` у любой команды `signals learn`.

### Измерения и цели {#learn-measures}

Измерение считает проверка по выходам графа. Числовые поля `freq` и `delay` можно задать текстом с параметрами варианта: `freq = "{{f}}"`, `freq = "2 * {{f}}"`. `a` и `b` — узел или порт полосы (`dwt.d1`). Вместо `b` можно указать `ref`: тогда эталоном служит тот же узел эталонного решения, прогнанного на том же входе.

| Вид | Что считает |
|---|---|
| `max_error` | наибольшая по модулю разность `a` и `b` после выравнивания задержки (`delay` — число или `auto`), без `trim` отсчётов с краёв |
| `snr` | SNR сигнала `a` относительно `b` в дБ, с тем же выравниванием |
| `delay` | задержка `a` относительно `b` по максимуму взаимной корреляции |
| `tone_db` | уровень синусоиды частоты `freq` в `a`, дБ |
| `gain_db` | разность уровней тона `freq` в `a` и `b`, дБ |
| `max_abs`, `energy`, `rms_db`, `length` | пик, энергия, уровень RMS и длина сигнала `a` |
| `kept` | доля ненулевых коэффициентов в `a` |
| `field` | поле `field` отчёта узла `a` |
| `samples` | отсчёты `a` целиком — для ответов-векторов |
| `count` | число узлов блока `block` (обойдённые узлы не считаются) |
| `param` | значение параметра `node.param` |

Цель — ровно одно из:

- `when` — выражение над измерениями и параметрами: `err <= 1e-12 && n == 10`. Работают `+ - * / ^`, сравнения, `&& || !`, `abs min max sqrt log10` и `pi`;
- `through = { from, to, block }` — каждый путь от `from` к `to` проходит через блок `block`; вместо типа блока можно назвать узел: `block = "n"`;
- `forbid = [...]` — запрещённые блоки;
- `require = { block = число }` — обязательные блоки; считаются только узлы, от которых сигнал доходит до измеряемых выходов, так что мёртвые ветки не помогают;
- `probe = "имя"` — в графе есть щуп с таким именем.

У задания-ответа целей нет, есть раздел `[answer]`: `type` (`number`, `integer`, `vector`, `choice`), `expected` — имя измерения на эталонном решении или ответ с плейсхолдерами (`"{{a}} + 1"`), `tol` и `rel` — допуск, `options` — варианты для выбора (программа показывает их в порядке, перемешанном по варианту; ответ — номер, текст варианта или значение после «=»), `verify` — условие на измерения эталона, которое подтверждает выбранный ответ.

### Тексты заданий {#learn-text}

`ru.md` и `en.md` устроены одинаково:

```
# Название

Условие: абзацы с формулами $…$ и ссылками на книгу {#раздел}.

## Цели {#goals}

1. Текст первой цели — по одному пункту на каждую [[goal]].

## Подсказки {#hints}

1. Первая подсказка.
2. Вторая.

## Разбор {#solution}

Решение с числами.
```

Плейсхолдеры в тексте и в `.sig`: `{{x}}` — параметр варианта, `{{expected}}` — эталонный ответ, `{{m.err}}` — измерение на эталонном решении. Числа в разборе лучше брать из плейсхолдеров: тогда текст никогда не разойдётся с программой.

### Проверка курса {#learn-lint}

```
signals learn lint --course моя-папка --variants 5
```

Для каждого задания и вариантов 1…N команда проверяет:

- эталонное решение засчитывается, а заготовка — нет;
- каждый файл из `cheats/` проваливается;
- `verify` истинно;
- у `ru.md` и `en.md` одинаковое число подсказок;
- все разделы книги и все плейсхолдеры находятся.

Встроенный курс проходит ту же проверку в тестах программы.
