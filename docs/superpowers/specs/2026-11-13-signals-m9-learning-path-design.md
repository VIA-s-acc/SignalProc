# M9 «Учебный путь» — проект

Строка M9 из `03-design.md` §13: задания с автопроверкой прямо в программе, прогресс, подсказки по шагам, связь с «Учебником». Каждое задание проверяется тестом, путь проходит от первой свёртки до шумоподавления. Пользователь просил очень богатое содержание и на вопрос «кто и как проходит путь» ответил «решай сам». Поэтому все решения ниже — мои, пользователь может их оспорить.

## Для кого и зачем

- **Кто.** Студент курса по банкам фильтров и вейвлетам (Strang–Nguyen, как в книге программы). Он сидит один за компьютером: дома или на практикуме, как в `examples/prak1`. Книга у него уже есть — «Учебник» на вкладке 9.
- **Зачем.** Прочитать про банк Хаара мало: нужно своими руками собрать банк, увидеть, что он восстанавливает сигнал, и понять, почему испорченный f₁ даёт наложение. Задание даёт цель, программа сразу говорит, достигнута ли она, а подсказки ведут, не выдавая ответа.
- **Что остаётся в конце.** Решённые задания с графами и ответами и отчёт в Markdown, который можно сдать преподавателю.
- **Преподаватель.** Может написать свой курс в том же формате, что и встроенный, и проверить его командой `signals learn lint`.

## Цели

1. Встроенный курс из 12 глав и 66 заданий: от свёртки до шумоподавления и классических фильтров (оглавление — ниже).
2. Два вида заданий: «собери граф» (проверяется прогоном графа) и «найди ответ» (число, целое, вектор или выбор).
3. Проверка в интерфейсе и в командной строке одним и тем же кодом.
4. Проверку графа не обойти очевидными способами: скрытые входы, условия на устройство графа, закреплённые узлы.
5. У каждого студента свой вариант чисел: параметры задания зависят от номера варианта.
6. Прогресс, подсказки по одной, разбор после решения, отчёт.
7. Связь с «Учебником» в обе стороны: из задания — в разделы, из раздела — к заданиям.
8. Тест на каждое задание: решение проходит, заготовка не проходит, известные обходы не проходят, оба языка полны.

## Не цели

- Проверка состояния экранов («выбери в «Конструкторе» разбиение…»). Такие задания формулируются как поиск ответа: экран служит инструментом, проверяется число или вектор. Поэтому каждое задание проверяется и из командной строки.
- Экзаменационная система: без шифрования, учётных записей и сети. Прогресс — обычный файл.
- Блок `assert` и выражения в полях (С29 и С42 из `04-backlog.md`) — отдельные PR после курса. Вычислитель выражений пишется так, чтобы они его переиспользовали.

## Анти-цели (провал, даже если всё работает)

- Задания запираются до решения предыдущих. Порядок только рекомендуется, открыто всё.
- Очки, значки и серии.
- Задание пересказывает книгу. Текст короткий, теория — ссылками на разделы.
- Число в тексте разбора расходится с программой. Числа в разборе подставляются из расчёта, как живые значения в карточках.
- Задание засчитывается за провод `x → check.in` или за переписанный в `samples` ответ.

## Подходы

1. **Задания внутри конвейера: проверка блоком `assert` в самом графе.** Просто, но студент видит и может поменять проверку. Заданиям-ответам нужен отдельный механизм.
2. **Задания по состоянию экранов: экраны публикуют живые значения, задание ставит на них условия.** Задания охватывают все вкладки, но их нельзя проверить без интерфейса, а каждый экран надо учить публиковать нужные факты.
3. **Выбрано: отдельный проверяющий с описанием задания в файлах.** Задание — каталог: условие, заготовка, эталонное решение, измерения и цели. Проверяющий сам прогоняет граф студента и сам считает измерения, поэтому ему не нужно доверять узлам студента. Ответы сравниваются с эталоном, посчитанным той же программой. Работает в CLI, в интерфейсе и в тестах одинаково.

## Формат задания

Курс — каталог глав, глава — каталог заданий:

```
resources/learn/course/
  course.toml                    # название курса ru/en, порядок глав
  04-haar/
    chapter.toml                 # название главы ru/en, разделы книги
    03-build-bank/
      task.toml                  # машинная часть
      start.sig                  # заготовка (для заданий-графов)
      solution.sig               # эталонное решение
      cheats/direct-wire.sig     # обходы, которые обязаны провалиться
      ru.md                      # условие, подсказки, разбор
      en.md
```

Идентификатор задания — «номер главы.номер задания» по порядку каталогов (`4.3`).

**`task.toml`:**

```toml
kind = "graph"                   # graph | answer
open = "pipeline"                # вкладка, которую открывает «Начать»
theory = ["haar-walkthrough", "fb-distortion-alias"]

[[param]]                        # варианты: значения зависят от номера варианта
name = "x"
kind = "ints"                    # int | ints | real | choice
count = 8
min = -9
max = 9

[input]                          # скрытые входы (только для graph)
node = "x"                       # узел-источник samples в заготовке
hidden = 4                       # сколько случайных входов проверить дополнительно

locked = ["x"]                   # узлы, которые нельзя менять

[[measure]]
name = "err"
kind = "max_error"               # см. список измерений
a = "sum"
b = "x"
delay = "auto"

[[measure]]
name = "ds"
kind = "count"
block = "downsample"

[[goal]]
when = "err <= 1e-12"
[[goal]]
when = "ds >= 2"
[[goal]]
through = { from = "x", to = "sum", block = "downsample" }
[[goal]]
forbid = ["dwt", "idwt", "swt", "iswt", "lift53", "ilift53", "lift97", "ilift97", "wpt", "iwpt", "dtcwt", "idtcwt", "mra"]
```

Для `kind = "answer"`:

```toml
[answer]
type = "vector"                  # number | integer | vector | choice
expected = "samples(y)"          # измерение на solution.sig или число
tol = 1e-9                       # абсолютный допуск; rel = … — относительный
options = ["z = -1", "z = 1", "z = 0"]   # только для choice
```

**`ru.md` и `en.md`:** первый абзац под заголовком — условие. Затем `## Подсказки {#hints}` — нумерованный список, по одной подсказке за раз. Затем `## Разбор {#solution}`. В тексте работают формулы `$…$` и плейсхолдеры: `{{x}}` — параметры варианта, `{{expected}}` — эталонный ответ, `{{m.err}}` — измерение на эталонном решении. В английском те же разделы с `{#hints}` и `{#solution}`, число подсказок одинаково.

**Плейсхолдеры в `.sig`.** В `start.sig` и `solution.sig` можно писать `{{x}}`. Подстановка — текстовая, до разбора файла.

## Измерения

Каждое измерение — число или вектор. Его считает проверяющий по выходам узлов графа студента, а не узлы студента. `a` и `b` — узел или порт (`dwt.d1`).

| Вид | Что считает |
|---|---|
| `max_error` | max\|a − b\| после выравнивания задержки (`delay` = число или `auto`), с обрезкой краёв `trim` |
| `snr` | SNR a относительно эталона b в дБ, с тем же выравниванием |
| `delay` | задержка a относительно b по максимуму корреляции, в отсчётах |
| `tone_db` | уровень синусоиды частоты `freq` в a, дБ (ДПФ с окном Ханна на целом числе периодов) |
| `gain_db` | `tone_db(a) − tone_db(b)` на частоте `freq` |
| `max_abs`, `energy`, `rms_db`, `length` | по сигналу a |
| `kept` | доля ненулевых коэффициентов в a (порт коэффициентов) |
| `field` | поле отчёта узла a: `field = "entropy"` |
| `samples` | отсчёты a как вектор (для ответов) |
| `count` | число узлов блока `block` в графе |
| `param` | значение параметра `node.param` |

Цель — выражение над измерениями и параметрами (`err <= 1e-12 && kept <= 0.10`), либо структурное условие: `through` (каждый путь от `from` к `to` проходит через блок `block`), `forbid` (запрещённые блоки), `require` (обязательные блоки с числом), `probe` (щуп с таким именем есть).

**Выражения** — свой маленький разборщик: числа, имена, `+ − * / ^`, сравнения, `&& || !`, скобки, функции `abs min max sqrt log10`. Он отдельный модуль, его потом возьмут блок `assert` и числовые поля интерфейса.

## Проверка

1. Подставить параметры варианта в `start.sig`, `solution.sig` и тексты.
2. Задание-граф:
   - проверить закреплённые узлы: тип и параметры совпадают с заготовкой;
   - прогнать граф студента на входе варианта и посчитать измерения;
   - проверить цели;
   - повторить прогон и цели на `hidden` скрытых входах: узел `input.node` получает другие отсчёты того же размера через `apply_set`, случайные с зерном от варианта.
   
   Засчитано, если все цели выполнены на всех входах.
3. Задание-ответ: разобрать ответ студента (вектор — числа через пробел или запятую, каждое число — выражение: `sqrt(2)/2`), посчитать эталон на `solution.sig` или взять число и сравнить с допуском.
4. Результат: список целей с измеренным значением и порогом, итог, время. Ошибка графа (не тот тип порта, нет узла) — понятное сообщение, а не провал без причины.

Проверка идёт фоновой задачей и отменяется `Esc`, как прогон конвейера.

## Варианты

- Номер варианта — целое 1…999 в файле прогресса. По умолчанию 1; студент задаёт его сам: `signals learn variant 17` или в интерфейсе.
- Генератор параметров детерминирован: одно и то же задание с тем же вариантом даёт те же числа на любой машине (свой ГПСЧ, не `std::uniform_*_distribution`, у которого реализация зависит от библиотеки).
- Отчёт пишет номер варианта, чтобы преподаватель мог проверить ответ той же командой.

## Прогресс и отчёт

- Файл `learn.toml` в папке настроек рядом с `session.toml`. В нём имя студента, вариант и по каждому заданию:
  - состояние: открыто, решено, решено с разбором;
  - число попыток и открытых подсказок;
  - время решения и ответ.
- Решённый граф копируется в `learn/<id>.sig` в папке настроек.
- Рабочий граф задания лежит в `learn/work/<id>.sig`: «Начать» открывает его в «Конвейере», и обычное `Ctrl+S` сохраняет работу.
- `signals learn report -o report.md` и пункт палитры «Задания: отчёт…» пишут отчёт:
  - шапка: имя, вариант, версия программы, дата;
  - таблица глав и заданий;
  - по каждому решённому заданию: цели с числами, ответ или граф.

## Интерфейс

**«Теория ▸ Задания» — четвёртая вложенная вкладка.**
- Слева — дерево глав и заданий с отметками ✓ (решено), ◐ (решено с разбором), ● (текущее) и счётчиком «12/66».
- В центре — условие с формулами.
- Справа или ниже — панель целей (каждая цель: ✓/✗/·, измерение, порог) и панель подсказок.
- Для заданий-ответов — поле «Ответ:», `Enter` проверяет.
- Клавиши:
  - `Enter` — «Начать»: открывает нужную вкладку, для графа загружает рабочий граф;
  - `h` — следующая подсказка;
  - `s` — разбор: после решения сразу, до решения — с подтверждением, тогда задание помечается «с разбором»;
  - `Tab` — панели;
  - `z` — панель на весь экран;
  - `t` — разделы книги к заданию.
- Списки листаются, ничего не обрезается молча, на 80×24 панели складываются в стопку.

**Строка задания на всех вкладках.** Пока задание активно, над строкой подсказок видна одна строка: «◆ 4.3 Собери банк Хаара · цели 2/4 · F2 проверить · F3 подсказка». На узком экране она сжимается до «◆ 4.3 · 2/4 · F2». Щелчок открывает задание. `F2` проверяет откуда угодно; если задание-ответ, открывается поле ответа.

**Автопроверка.** После каждого прогона в «Конвейере» рабочего графа активного задания цели пересчитываются сами, `F2` не нужен. Скрытые входы при этом тоже прогоняются.

**Палитра:** «Задания: открыть…», «Задания: проверить», «Задания: подсказка», «Задания: отчёт…», «Задания: вариант…».

**«Учебник».** У разделов, на которые ссылаются задания, внизу строка «Задания: 4.3 Собери банк Хаара, 4.5 …»; щелчок открывает задание.

## Командная строка

```
signals learn                         # главы, задания, прогресс
signals learn show 4.3                # условие (с подсказками, которые уже открыты)
signals learn start 4.3 [-o 4.3.sig]  # записать заготовку
signals learn check 4.3 [файл.sig | --answer "1 2 3"] [--json]
signals learn hint 4.3                # открыть следующую подсказку
signals learn solution 4.3            # разбор (с подтверждением флагом --yes до решения)
signals learn variant [N]             # показать или задать вариант
signals learn report [-o report.md]
signals learn lint [каталог курса]    # проверить курс: решения, заготовки, обходы, тексты
```

Все команды понимают `--lang`, `--course DIR` (свой курс вместо встроенного) и `--variant N` (разово). Код выхода `check`: 0 — засчитано, 3 — цели не выполнены, 1 — ошибка задания или графа (как у `signals run`).

## Курс (66 заданий)

Г — задание-граф, О — ответ. В скобках — что проверяется.

**0. Знакомство** (`#conventions`)
- 0.1 Г: поставь щуп на выход (`probe`)
- 0.2 О: пик сигнала в файле (число, «Сигнал»)
- 0.3 О: SNR из отчёта примера `denoise` (число, `r` в «Конвейере»)

**1. Свёртка и ЛИС-системы** (`#lti`, `#toeplitz-convolution`, `#toeplitz-circulant`)
- 1.1 О: свёртка вручную (вектор)
- 1.2 Г: свёртка в конвейере (совпадение со скрытыми входами)
- 1.3 О: длина полной свёртки (целое)
- 1.4 О: элемент тёплицевой матрицы (число, «Матрица»)
- 1.5 О: круговая свёртка (вектор)
- 1.6 Г: скользящее среднее как ФНЧ (`gain_db` тона ≤ −20 дБ, DC проходит)
- 1.7 О: импульсная характеристика «чёрного ящика» (вектор)

**2. Частотные характеристики** (`#freq`)
- 2.1 О: частота −3 дБ у h₀ Хаара (число, «Фильтры»)
- 2.2 О: АЧХ db4 и db2 при ω = 0,75π (число)
- 2.3 О: ГВЗ симметричного КИХ (целое)
- 2.4 О: где нуль H₀ Хаара (выбор)
- 2.5 О: нулевые моменты db3 (целое)
- 2.6 Г: ФНЧ по требованиям (тон f₁ теряет < 1 дБ, тон f₂ подавлен ≥ 40 дБ)

**3. Прореживание и растяжение** (`#multirate`)
- 3.1 О: частота наложения после ↓M (число)
- 3.2 Г: убрать наложение перед ↓2 (уровень копии ≤ −40 дБ)
- 3.3 О: ↓2, затем ↑2 (вектор)
- 3.4 Г: тождество Нобла (две ветви совпадают до 10⁻¹²)
- 3.5 Г: полифазная свёртка без ↓2 (совпадение с эталоном, `downsample` запрещён)
- 3.6 О: L и M для 44 100 → 48 000 (вектор)

**4. Банк Хаара** (`#haar`)
- 4.1 О: коэффициенты a вручную (вектор)
- 4.2 О: коэффициенты d вручную (вектор)
- 4.3 Г: собери банк Хаара из блоков (ПВ < 10⁻¹² на скрытых входах, путь через ↓2, без DWT)
- 4.4 О: задержка восстановления банка db2 (целое)
- 4.5 О: ошибка при испорченном f₁ (число)
- 4.6 Г: два уровня Хаара из блоков (ПВ < 10⁻¹²)
- 4.7 О: доля энергии деталей (число, Парсеваль)

**5. Двухканальные банки** (`#two-channel`)
- 5.1 О: какой синтез убирает наложение (выбор)
- 5.2 Г: банк db2 с полным восстановлением (ПВ и задержка 3)

- 5.4 О: сколько разбиений у P₀ степени 6 (целое, «Конструктор»)

- 5.6 О: h₀ ортогонального разбиения db2 (вектор)
- 5.7 Г: банк 5/3 (bior2.2) с полным восстановлением

**6. Матрицы банков** (`#fb-matrices`)
- 6.1 О: элемент матрицы анализа Хаара при N = 8 (число, «Матрица»)
- 6.2 О: число коэффициентов при периодизации и симметричном продолжении (вектор)
- 6.3 О: число обусловленности матрицы 9/7 при N = 16 (число)
- 6.4 О: число ненулевых элементов многоуровневой W (целое)
- 6.5 О: модули собственных чисел циркулянта (вектор)

**7. Вейвлеты и DWT** (`#wavelets`, `#dwt-mallat`)
- 7.1 Г: нулевые моменты на квадратичном сигнале (внутренние d₁ < 10⁻⁹)

**8. Без прореживания, пакеты, CWT** (`#swt-modwt`, `#wavelet-packets`, `#cwt`)
- 8.1 О: как меняется энергия d₁ DWT при сдвиге на отсчёт (число)
- 8.2 Г: SWT не зависит от сдвига (до 10⁻¹²)
- 8.3 О: число листьев лучшего базиса (целое)

**9. Сжатие** (`#audio-compression`, `#lift-53`)

## Тесты

- **Модульные.** Выражения; каждое измерение (с эталоном numpy там, где это не очевидная формула); структурные условия; разбор `task.toml` с понятными ошибками и номером строки; генератор вариантов (одинаковые числа на всех платформах); прогресс туда и обратно; отчёт сравнивается с эталонным файлом.
- **Курс.** Для каждого задания и вариантов 1, 2, 3:
  - `solution.sig` или эталонный ответ засчитывается;
  - `start.sig` не засчитывается;
  - каждый файл в `cheats/` не засчитывается;
  - у ru и en одинаковое число подсказок, оба есть;
  - все `{#id}` книги и все плейсхолдеры разрешаются.

  Это и есть «каждое задание проверяется тестом». Тот же код — у `signals learn lint`.
- **Интерфейс.** Снимки «Задания» и строки задания на 150×44 и 80×24, общий тест «всё помещается», справочник клавиш генерируется и сверяется.
- **CLI.** Каждая подкоманда, коды выхода, `--json`.
