# M10 «Лёгкий вход» — проект

Строка M10 из `03-design.md` §13: установка одной командой, README с анимациями главных экранов, английская версия на виду, первый запуск ведёт к примеру. Критерий из таблицы: установка на чистой машине за минуту, README показывает каждый экран.

Пользователь выбрал способ установки: **скрипты в этом репозитории и свой репозиторий Homebrew (tap)**. winget в M10 не входит. Остальные решения ниже — мои, они перечислены в конце.

## Для кого и зачем

- **Кто.** Человек, который впервые открыл страницу репозитория на GitHub: студент с практикума, коллега, рекрутер, читатель статьи о банках фильтров. Он не знает программу, может не читать по-русски и не хочет собирать C++.
- **Что он должен успеть за пять минут.** Понять по README, что это и как выглядит, поставить программу одной командой, запустить её и сразу увидеть работающий пример, а не пустой экран.
- **Почему сейчас.** Программа полна (0.8.0: 136 блоков, книга, 66 заданий), но вход в неё — ручная распаковка архива, снятие карантина на macOS, README только на русском и без картинок, пустая вкладка при первом запуске.

## Цели

1. Установка одной командой на macOS (Apple Silicon и Intel), Linux x86_64 и Windows x86_64, с проверкой контрольной суммы, без `sudo` и без сборки.
2. `brew install VIA-s-acc/signals/signals` на macOS и Linux; формула обновляется сама при каждом выпуске.
3. Дополнение команд для bash, zsh и fish и man-страница (пункты Н65 и Н66 из `04-backlog.md`): установка их раскладывает.
4. Первый запуск без сохранённого сеанса открывает стартовую панель: пример, первое задание, свой файл.
5. README на английском (`README.md`) и на русском (`README.ru.md`) с изображениями каждого экрана и несколькими анимациями. Изображения делает сама программа.
6. Всё это проверяется в CI: скрипты, формула, панель, наличие изображения у каждого экрана.

## Не цели

- winget, Scoop, пакеты apt/rpm, отправка в homebrew-core. Манифест winget — отдельная работа после M10, с согласия пользователя.
- Подпись и нотаризация сборок macOS и Windows: нужны платные учётные записи разработчика.
- Сборки для Linux aarch64 и Windows ARM64 (Windows ARM64 запускает сборку x86_64 через эмуляцию).
- Видеофайл. README на GitHub не показывает видео из репозитория, поэтому вместо видео — анимированные SVG.
- Отдельный выпуск. По `04-backlog.md` версия 0.9.0 выходит после M11; M10 копится в `main` под `[Unreleased]`.

## Анти-цели (провал, даже если всё работает)

- Скрипт установки просит `sudo`, пишет вне домашней папки пользователя по умолчанию или ставит файл, не сверив контрольную сумму.
- Изображения в README не из программы (макеты) или тихо устаревают: делать их можно только инструментом галереи из этого репозитория.
- Стартовая панель мешает: появляется снова после закрытия, открывается при запуске с файлом или в скриптах.
- Ломаются ссылки на старые выпуски: архивы 0.8.0 и раньше остаются как есть, ноутбук `prak1` ссылается на них.

## Подходы

**Установка** (выбрал пользователь):

- A. Только скрипты в репозитории (`install.sh`, `install.ps1`). Ничего не публикуется снаружи; нет привычного `brew install`.
- **B. Скрипты и свой tap Homebrew** — выбран. Отдельный репозиторий `VIA-s-acc/homebrew-signals` с формулой; сборка выпуска обновляет её токеном. Цена — один репозиторий и один секрет.
- C. B и winget. Каждый выпуск — PR в репозиторий Microsoft с их проверкой; отложено.

**Изображения экранов** (моё решение):

- Внешний записыватель терминала (vhs, asciinema и agg). Нужны сторонние инструменты и настоящий терминал, картинка зависит от шрифтов машины, записи трудно повторить.
- **Отрисовка самой программой** — выбрано. Кадр ftxui (`ftxui::Screen`) уже есть в тестах экранов; из ячеек кадра с цветами строится SVG. Сценарии экранов — код в репозитории, повторяются одной командой, цвета берутся из темы программы.

## Устройство

### 1. Сборки выпуска

- **macOS — универсальная сборка** (`arm64` и `x86_64` в одном файле, `CMAKE_OSX_ARCHITECTURES="arm64;x86_64"`, минимум macOS 14). Архив называется `signals-vX.Y.Z-macos-universal.tar.gz` и заменяет `macos-arm64` начиная со следующего выпуска. Проверка сборки в CI: `lipo -archs` даёт оба среза, `signals check` проходит на `arm64` и, если на машине CI есть Rosetta (`arch -x86_64 /usr/bin/true` успешен), на `x86_64`; без Rosetta — предупреждение в журнале, не ошибка. Сборка с двумя архитектурами сразу ещё не пробовалась (зависимости тянутся через FetchContent). Если она не собирается, запасной путь — два прохода сборки на той же машине (`arm64` и `x86_64`) и склейка `lipo -create`; имя архива и всё остальное не меняются.
- **Содержимое архивов.** К `signals`, `README.md` и `LICENSE` добавляются `README.ru.md`, `man/signals.1` и `completions/` (`signals.bash`, `_signals`, `signals.fish`). Страница и дополнения создаются при упаковке запуском собранной программы (`--lang en`). В zip для Windows — только `README.ru.md` сверх нынешнего.

### 2. Дополнение команд и man (Н65, Н66)

- `signals completions bash|zsh|fish` печатает скрипт дополнения. Он строится обходом дерева CLI11: подкоманды любой вложенности (`filter info`, `learn check`), ключи каждой подкоманды, допустимые значения там, где у ключа есть `CLI::IsMember` (например, `--rule bayes|visu|sure|minimax`), имена файлов для позиционных аргументов-путей. В zsh и fish — описания ключей из CLI11 на текущем языке.
- `signals man` печатает страницу `signals(1)` в roff: NAME, SYNOPSIS, DESCRIPTION, COMMANDS (каждая подкоманда с ключами и описаниями), ENVIRONMENT (`SIGNALS_LANG` и другие переменные, которые читает программа), FILES (папка настроек, `learn.toml`, сеанс), EXIT STATUS, SEE ALSO. Язык — текущий (`--lang`), в архивах — английский.
- Обе команды не открывают интерфейс и работают без терминала.

### 3. `install.sh` (macOS и Linux)

Запуск: `curl -fsSL https://raw.githubusercontent.com/VIA-s-acc/SignalProc/main/install.sh | sh`.

- POSIX `sh`, `set -eu`. Нужны `curl` или `wget`, `tar`, `shasum` или `sha256sum`; без них — понятная ошибка, что поставить.
- Настройки — переменными окружения (при `curl | sh` ключи неудобны) и теми же ключами при запуске файлом или через `sh -s --`:
  - `SIGNALS_VERSION` / `--version vX.Y.Z` — по умолчанию последний выпуск;
  - `SIGNALS_INSTALL_DIR` / `--dir DIR` — по умолчанию `$HOME/.local/bin`;
  - `SIGNALS_RELEASE_URL` — основа адресов выпуска, для тестов (`file://…`).
- Последний выпуск определяется без `jq`: по перенаправлению `https://github.com/VIA-s-acc/SignalProc/releases/latest` (curl) или через API GitHub (wget).
- Платформа: `Darwin` любой архитектуры → `macos-universal`; если в выпуске такого архива нет, а машина `arm64` — `macos-arm64` (выпуски до 0.9.0); `Linux x86_64` → `linux-x86_64`. Остальное — ошибка со ссылкой на сборку из исходников.
- Скачивает архив и `SHA256SUMS` во временную папку (удаляется при выходе), сверяет сумму: при несовпадении — ошибка, ничего не ставится.
- Архив распаковывается с верхней папкой `signals-vX.Y.Z-<платформа>/` (так он устроен с 0.6.0); файлы берутся из неё.
- Ставит `signals` в папку установки (`chmod 755`), man-страницу в `$HOME/.local/share/man/man1`, дополнения bash в `$HOME/.local/share/bash-completion/completions/signals`, fish в `$HOME/.config/fish/completions/signals.fish`. Для zsh печатает одну строку, как подключить. Для архивов без man и дополнений (до 0.9.0) эти шаги пропускаются.
- На macOS снимает атрибут карантина, если он есть.
- Повторный запуск обновляет: «updated 0.8.0 → 0.9.0». Тот же выпуск — «already installed», без ошибки.
- В конце: путь, `signals --version`, строка для `PATH`, если папки в нём нет (для оболочки пользователя), и следующий шаг: `signals` откроет стартовую панель.
- Сообщения — на английском.

### 4. `install.ps1` (Windows)

Запуск: `irm https://raw.githubusercontent.com/VIA-s-acc/SignalProc/main/install.ps1 | iex`.

- Работает в Windows PowerShell 5.1 и PowerShell 7. Те же `SIGNALS_VERSION`, `SIGNALS_INSTALL_DIR`, `SIGNALS_RELEASE_URL`.
- Архитектура x64 и ARM64 → `windows-x86_64`.
- Папка по умолчанию `$env:LOCALAPPDATA\Programs\signals`. Сверяет SHA-256 (`Get-FileHash`), распаковывает, добавляет папку в `PATH` пользователя (реестр HKCU, без прав администратора) и в текущий сеанс.
- В конце — версия, следующий шаг и совет запускать в Windows Terminal.

### 5. Homebrew

- Репозиторий `VIA-s-acc/homebrew-signals` (публичный): `Formula/signals.rb` и короткий README. Его создаёт исполнитель плана командой `gh repo create` в PR 2 — пользователь на это согласился («свой tap»). Первая формула — на 0.8.0: macOS только Apple Silicon (`macos-arm64`), Linux x86_64; суммы берутся из опубликованного `SHA256SUMS` выпуска 0.8.0 тем же скриптом подстановки.
- Формула ставит готовую сборку: `on_macos` — универсальный архив (или `macos-arm64` для 0.8.0 и только `on_arm`), `on_linux` + `on_intel` — `linux-x86_64`. `bin.install "signals"`, `man1.install "man/signals.1"` и `generate_completions_from_executable(bin/"signals", "completions")`, когда в выпуске они есть. `test do`: `signals --version` совпадает с версией формулы, `signals check` проходит.
- Шаблон формулы и скрипт, который подставляет версию и суммы из `SHA256SUMS`, лежат в этом репозитории (`packaging/homebrew/`). Скрипт сам выбирает вариант универсальный/arm64 по составу `SHA256SUMS`.
- Новое задание в `release.yml` после публикации: если секрета `HOMEBREW_TAP_TOKEN` нет — предупреждение и пропуск, не ошибка; если есть — формула записывается в tap и отправляется коммитом `signals X.Y.Z`.
- Шаг пользователя (один раз): создать fine-grained токен с правом Contents: write только на `homebrew-signals` и добавить его секретом `HOMEBREW_TAP_TOKEN` в `SignalProc`. Исполнитель токены не создаёт и не вводит. PR 2 готов и без токена: задание выпуска тогда пропускается с предупреждением, а формулу 0.8.0 исполнитель кладёт в tap сам.

### 6. Стартовая панель

- Показывается, когда `signals tui` (или `signals` без аргументов) запущен без файла и файла сеанса не было до запуска. У `SessionStore` появляется признак «сеанс новый»: файла нет. Файл, который есть, но не читается, новым сеансом не считается — панель не навязывается тому, кто программой уже пользовался. Без папки настроек сеанс не сохраняется, и панель показывается при каждом запуске — это допустимо: она закрывается одной клавишей.
- Не показывается при запуске с файлом и после закрытия. Закрытие панели или выбор пункта сразу записывает сеанс (тот же файл, что программа и так пишет при выходе), так что после аварийного выхода панель не вернётся. Если программу убили, пока панель открыта, она покажется снова — это допустимо.
- Открывается снова из палитры команд: «Стартовая панель» / «Start panel».
- Содержимое: название и версия, одна строка о программе, три пункта (цифра, `Enter` или щелчок):
  1. **Пример: шумоподавление** — открывает «Конвейер» с новым встроенным примером `first_steps.sig` и сразу его запускает. Пример не читает файлов: сгенерированный сигнал, шум, DWT, порог, обратное DWT, щупы «шумный» и «очищенный», отчёт SNR. Прогон — доли секунды. Файл лежит в `examples/` и встраивается в программу тем же `signals_embed_dir`, что и остальные примеры (`src/pipeline/CMakeLists.txt`, `pipeline::examples()`), поэтому есть и в установке без папки ресурсов.
  2. **Учебный путь: задание 0.1** — делает 0.1 текущим заданием и открывает «Теория ▸ Задания».
  3. **Открыть свой звуковой файл…** — существующий диалог открытия на вкладке «Сигнал».
- Ниже — строка главных клавиш: `1`–`9` вкладки, `Ctrl+P` палитра, `F1` справка, `q` выход (точные клавиши — по нынешней раскладке). `Esc` закрывает панель.
- Тексты через i18n, ru и en. Правила панелей: узкая раскладка (80×24), без обрезки, листание при нехватке места, мышь.

### 7. Галерея экранов

- **Отрисовщик кадра в SVG** (`src/tui/render/svg_frame.{hpp,cpp}`): `ftxui::Screen` → SVG. Каждая ячейка стоит в своей позиции сетки (координата каждого знака задаётся явно), поэтому подмена шрифта на машине читателя не сбивает выравнивание. Соседние ячейки одного стиля сливаются; фон — прямоугольниками по отрезкам. Цвет, жирность, тусклость, подчёркивание, инверсия — из ячейки. Шрифты: `ui-monospace, SFMono-Regular, Menlo, Consolas, "DejaVu Sans Mono", "Liberation Mono", monospace`. Рамка окна — скруглённый прямоугольник с полями, без поддельных кнопок окна.
- **Анимация**: последовательность кадров с длительностями, смена кадров стилем CSS `@keyframes` внутри SVG, повтор по кругу. Строки, одинаковые в нескольких кадрах, описываются один раз (`<defs>` и `<use>`).
- **Инструмент** `signals-gallery` (`tools/gallery/`, собирается по ключу CMake, по умолчанию выключен): строит модели и экраны как в тестах интерфейса (`make_app_models`, `make_app_screens`, `make_shell`), проигрывает сценарии клавиш и мыши, ждёт окончания фоновых задач перед каждым кадром и пишет SVG в `docs/images/en/` и `docs/images/ru/` (`--lang`). Размер кадра — 150×44. Звук для «Сигнала» и соседних экранов — `resources/samples/test.wav`.
- Мышь в сценариях есть: тестовая оснастка (`tests/tui/harness.hpp`) уже умеет щелчок, колесо, протяжку и правый щелчок; галерея берёт те же события.
- **Сценарии**: по одному статичному изображению на каждый из 15 маршрутов оболочки (таблица `routes` в `src/tui/shell/shell.cpp`: 9 вкладок, у «Спектра», «Конструктора» и «Теории» есть подвкладки) (`signal`, `spectrum`, `resample`, `tempo`, `filters`, `designer`, `diagram`, `decomposition`, `processing`, `pipeline`, `matrix`, `explain`, `under_the_hood`, `tutorial`, `learn`), имя файла — имя маршрута. И четыре анимации: обход вкладок (`tour`), прогон примера в «Конвейере» с переключением щупов (`pipeline-run`), проверка задания с переходом целей в ✓ (`learn-check`), выбор разбиения в «Конструкторе» с пересчётом откликов (`designer-pick`).
- **Размеры**: статичное изображение до 300 КБ, анимация до 1,5 МБ, все изображения одного языка до 8 МБ. Если не помещается — меньше кадров, не меньше экран.
- Изображения коммитятся в репозиторий и пересобираются одной командой (она записывается в README раздела разработки).

### 8. README

- `README.md` — английский, `README.ru.md` — русский, одинаковые по составу. Первая строка каждого — переключатель языка.
- Порядок: название и абзац о программе → анимация `tour` → **Install** (одна команда на систему, `brew`, ручная установка из архива, сборка из исходников) → **First steps** (стартовая панель, `signals learn`, примеры) → **Screens** (по разделу на вкладку: изображение и одна-две строки; подвкладки рядом) → Commands → Pipelines → Learning path → Documentation (книга и справочники на языке README) → Status → License.
- Изображения в `README.md` — из `docs/images/en/`, в `README.ru.md` — из `docs/images/ru/`.
- Ссылки на документацию в английском README ведут на `.en.md`.

### 9. CI

- `ci.yml`:
  - `shellcheck install.sh`;
  - проверка `install.sh` от начала до конца на Linux и macOS: собранная программа упаковывается как в выпуске в папку с `SHA256SUMS`, скрипт ставит её через `SIGNALS_RELEASE_URL=file://…` в временную папку; затем повтор (обновление/«already installed») и испорченная сумма (ошибка, ничего не поставлено);
  - то же для `install.ps1` в задании Windows;
  - подстановка формулы на тестовом `SHA256SUMS` (оба варианта) и `ruby -c`;
  - сборка `signals-gallery` и прогон в временную папку на Linux: каждый сценарий дал файл, размеры в пределах.
- Тесты программы (Catch2):
  - дополнения содержат каждую подкоманду и каждый ключ дерева CLI11; `bash -n` на скрипте bash (и `zsh -n`, `fish -n`, где есть);
  - man-страница содержит каждую подкоманду, `mandoc -T lint` или `groff -z` без ошибок, где есть;
  - стартовая панель: новый сеанс — видна; сеанс есть — нет; файл в аргументах — нет; каждый пункт ведёт куда нужно; помещается в 80×24;
  - `first_steps.sig` проходит и даёт SNR лучше входного;
  - отрисовщик SVG: цвета, слияние ячеек, позиции, экранирование `<`, `&`;
  - у каждого маршрута оболочки есть изображение в `docs/images/en` и `docs/images/ru`, и оба README на него ссылаются.
- Новый `install-check.yml` (запуск вручную и после выпуска): настоящие однострочники на чистых машинах GitHub — `curl … | sh` на Ubuntu и macOS, `irm … | iex` на Windows, `brew install VIA-s-acc/signals/signals` на macOS; время установки печатается, цель — меньше минуты.

## Разбиение на PR

Стопкой, каждый на предыдущем, как в M9:

1. Универсальная сборка macOS, `signals completions`, `signals man`, состав архивов.
2. `install.sh`, `install.ps1`, проверки в CI, шаблон формулы и задание выпуска для tap, `install-check.yml`; создание репозитория tap с формулой 0.8.0.
3. Стартовая панель и `first_steps.sig`.
4. Отрисовщик SVG, `signals-gallery`, изображения.
5. README на двух языках, документы, CHANGELOG.

## Критерии готовности

- На чистой машине GitHub (Ubuntu, macOS, Windows) однострочник ставит программу меньше чем за минуту, `signals --version` и `signals check` проходят (`install-check.yml`). После выпуска 0.9.0 — то же через `brew`.
- В `README.md` и `README.ru.md` есть изображение каждого из 15 экранов и четыре анимации, все созданы `signals-gallery`.
- Первый запуск с пустой папкой настроек показывает стартовую панель, каждый пункт работает.
- Сборка с `-Werror` на clang и GCC 16 (`-fno-range-for-ext-temps`), без имён `near`/`far`; все тесты проходят.

## Что остаётся строителю

- Точные тексты стартовой панели, README и сообщений скриптов.
- Длительности кадров и число кадров в анимациях в пределах размеров.
- Как ждать фоновых задач в галерее (через имеющийся планировщик задач или новый метод ожидания).

## Решения, принятые мной

1. Изображения делает сама программа, а не внешний записыватель — повторяемость и цвета темы.
2. `README.md` — английский, русский — `README.ru.md`.
3. Видео заменено анимированными SVG.
4. Универсальная сборка macOS: установка одной командой должна работать и на Intel.
5. Н65 и Н66 (дополнения и man) входят в M10: их раскладывает установка.
6. Сообщения скриптов установки — на английском.
7. Отдельного выпуска у M10 нет, 0.9.0 — после M11.
8. Стартовая панель — по признаку «файла сеанса не было», а не отдельным флагом; нечитаемый файл сеанса новым не считается; закрытие панели сразу записывает сеанс.
9. Если универсальная сборка за один проход не собирается — два прохода и `lipo -create`, имя архива то же. Срез `x86_64` запускается в CI только при наличии Rosetta, иначе проверяется только `lipo -archs`.
