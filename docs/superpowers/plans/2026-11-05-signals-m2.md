# Signals M2: звук, частотный анализ, шумоподавление — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Чтение и запись WAV во всех форматах, генераторы сигналов, операции над сигналом, ↓M/↑M с защитным фильтром Кайзера, полный частотный анализ фильтров, пороги и шумоподавление VisuShrink/BayesShrink и команды CLI `info`, `gen`, `dwt`, `denoise`, `resample`, `filter response`. Всё сверяется с независимыми оракулами.

**Architecture:**
- Новая библиотека `signals_io` (`src/io/`): WAV через dr_wav и генераторы.
- В `signals_core` новые модули:
  - `audio_buffer` — многоканальный буфер;
  - `signal_ops` — операции над сигналом;
  - `design/window_fir` — FIR-фильтр Кайзера;
  - `multirate` — ↓M/↑M;
  - `freq` — частотный анализ;
  - `process/threshold`, `process/shrink` — пороги и шумоподавление.
- CLI получает подкоманды.
- Оракулы:
  - PyWavelets 1.8.0 — пороги, тестовые сигналы;
  - SciPy 1.16.2 — `freqz`, `group_delay`, `chirp`, `kaiserord`, `firwin`, `upfirdn`;
  - scikit-image 0.25.2 — `_wavelet_threshold` для BayesShrink и VisuShrink.

  Эталоны генерирует `tools/gen_golden.py`, они коммитятся в репозиторий.

**Tech Stack:** как в M1, плюс dr_libs `wav-0.14.6` (dr_wav). В `tools/requirements.txt` добавляются `scipy==1.16.2` и `scikit-image==0.25.2`; проверено, что они ставятся в `tools/.venv` вместе с numpy 2.3.5.

**Spec:** `docs/03-design.md` — §6 соглашения, §7.2–7.3 функции, §10 корректность, §11 производительность, §13 строка M2. Теория — `docs/02-theory.md` (`#multirate-anti-alias`, `#freq`, `#audio-denoising`, `#cls-window-method`).

## Global Constraints

- Все ограничения M1: C++23, CMake ≥ 3.28, FetchContent, `double`, без `-ffast-math`, только пермиссивные зависимости, лицензия MIT.
- Код, идентификаторы, имена тестов и сообщения — на английском. Строки для человека в CLI — через `resources/i18n/ru.json`.
- Комментарий — только если без него код «упростят» в ошибку.
- Знаки Strang–Nguyen, фаза прореживания pywt, нормировка $\sum h_0=\sqrt2$, порядок $[a_J, d_J, \dots, d_1]$ — как в M1.
- Ошибки в `core` и `io` — через `Result<T>`. В `Errc` добавляется `io_error` для ошибок файловой системы и разбора файла.
- Каналы обрабатываются по отдельности; стерео никогда не перемешивается (регрессия 3).
- Внутренний диапазон отсчётов — ±1.
- Запись WAV по умолчанию: 24 бита, TPDF-dither, округление, ограничение с подсчётом (регрессия 5). NaN или Inf в данных — ошибка, файл не создаётся.
- Каждая проверка — именованный `CheckResult`. NaN никогда не проходит проверку.
- Код должен быть корректен и без правила P2718: не итерировать по подобъекту временного объекта (`for (x : f()[k])`). GCC 14 в CI это правило не поддерживает.
- Коммит — короткое предложение (~5 слов), без `Co-Authored-By`. `git push` — только с согласия пользователя.

## Review Focus

Пять входов, которые первыми ударят по пользователю. Каждый закреплён тестом в задаче-владельце.

1. **Битый или неподдерживаемый WAV:** обрезанный заголовок, не-WAV файл с расширением `.wav`, файл без кадров. Ожидается `io_error` или `invalid_argument` с понятным сообщением, без падения. Тест в Task 3.
2. **Тишина на входе шумоподавления:** все отсчёты нулевые, значит σ = 0. scikit-image на таком входе даёт NaN. У нас выход равен входу, без NaN. Тест в Task 13.
3. **Дробная частота полосы:** 44 100 / 2³ = 5512,5 Гц. В заголовок WAV пишется `std::lround` (5513), точное значение — в JSON-отчёт. Тест в Task 15.
4. **NaN или Inf в записываемом звуке:** ошибка `invalid_argument`, файла на диске нет. Тест в Task 4.
5. **Сигнал короче одного уровня разложения** в `signals dwt` и `signals denoise` (10 отсчётов и `sym8`): код 2 и русское сообщение «сигнал слишком короткий для фильтра». Тест в Task 15.

**Регрессии ревизии** (`docs/01-review-signalproc.md`):
- **3, стерео как моно** — Task 3 (у `test.wav` 2 канала по 450 686 кадров) и Task 13 (σ считается по каждому каналу).
- **4, частоты полос** — Task 15: полоса уровня j пишется с частотой fs/2^j.
- **5, переполнение int16** — Task 4: значения вне диапазона ограничиваются и считаются, а не заворачиваются.

### Task 4: Запись WAV

**Files:**
- Modify: `src/io/wav.hpp`, `src/io/wav.cpp`
- Test: `tests/io/test_wav_write.cpp`

**Interfaces:**
- Consumes: `AudioBuffer`, `read_wav`, `SampleFormat` (Task 3).
- Produces: `struct WavWriteOptions { SampleFormat format = SampleFormat::pcm_s24; bool dither = true; std::uint64_t dither_seed = 0x5eed; };` `struct WavWriteReport { std::size_t clipped_samples = 0; };` `core::Result<WavWriteReport> write_wav(const std::filesystem::path& path, const core::AudioBuffer& audio, const WavWriteOptions& options);`
- Решения:
  - Поддерживаются форматы `pcm_s16`, `pcm_s24`, `pcm_s32`, `float32`; остальные — `invalid_argument`.
  - Квантование: $q=\operatorname{round}(x\cdot2^{b-1}+d)$, где $d$ — TPDF-dither, разность двух `std::uniform_real_distribution<double>(0, 1)` от `std::mt19937_64(seed)`, в единицах LSB. Без dither $d = 0$. Затем ограничение отрезком $[-2^{b-1}, 2^{b-1}-1]$; каждое ограниченное значение увеличивает `clipped_samples`.
  - `float32` пишется как есть, ограничений нет.
  - Проверки до открытия файла: все каналы одной длины, частота — положительное целое ≤ 4 294 967 295, все отсчёты конечны. Иначе — `invalid_argument`, и файл не создаётся.
