# M12 «Формат графа» — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** формат `.sig` v2 с переводом старых файлов, переменными, своими блоками, участками и метками; живой скрипт Python; свои книги и свой курс в интерфейсе; всё, что зависит от формата, актуально и держится тестами.

**Architecture:**

- **Загрузка.** Вводится единая функция `load_sig`. Она разбирает текст по версии из заголовка и проводит документ по цепочке шагов перевода (`pipeline/migrate`).
- **Сборка.** Перед сборкой новый этап `pipeline/flatten` превращает документ v2 в плоский документ: подставляет переменные и участки, раскрывает вызовы блоков в узлы `вызов/узел` и переносит щупы. Существующий `Builder` строит граф из плоского документа, а исполнитель, кэш и щупы не меняются.
- **Python.** Узел плоского документа хранит параметры в исходном виде (`source`). Python-формы строят по ним выражения Python, поэтому скрипт живой.
- **Книги.** Свои книги — реестр `theory::Book` рядом со встроенной книгой. Ссылка вида `книга:раздел` ищется в этом реестре.

**Tech Stack:** C++23, CMake, Catch2, CLI11, nlohmann/json, toml++, fmt, FTXUI 7.0.3, miniz 3.0.2; Python 3.12 с numpy 2.3.5, scipy 1.16.2, PyWavelets 1.8.0, matplotlib 3.10.9; Node 20 (`node --test`); GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-11-17-signals-m12-graph-format-design.md`. Номера разделов ниже (§N, А.N) — разделы этого документа.

## Global Constraints

- Сборка с `-Werror` на clang и на GCC 16 с `-fno-range-for-ext-temps`; без идентификаторов `near` и `far` (MSVC).
- Комментарии в коде — только если без них код сломают, на английском. Имена, названия тестов, сообщения тестов и инструментов `tools/` — на английском. Текст интерфейса и сообщения CLI — через i18n (`resources/i18n/ru.json`, `en.json`), на обоих языках, в 80 колонок.
- Панели: `Tab`, `z`, масштаб графиков, узкая раскладка 80×24, листание, никакой тихой обрезки — для каждой новой панели, окна и вопроса. Высота экрана берётся из `screen_rows(ui)` (PR #78), а не из размера терминала.
- Каждая возможность доходит до всех мест таблицы §7 и приложения А: CLI, интерфейс, блоки, Python, `explain`, теория, VS Code, документы `docs/user/*` (ru и en), `keys.md`, `blocks.md` и `editors/vscode/data/blocks.*.json` (перегенерировать), CHANGELOG `[Unreleased]`. Что сознательно пропущено, говорится в PR.
- Формат пишется только в v2; v1 читается всегда. Все читатели — через `load_sig`; прямой вызов `parse_sig` вне `src/pipeline` запрещён, это проверяет тест (Task 3).
- Числа графа v1 после перевода совпадают с 0.9.0 бит в бит; граф со своими блоками — с развёрнутым руками бит в бит.
- Сверка Python: `max|a − b| ≤ tol · max(1, max|b|)`, `tol` = 10⁻¹², у блоков таблицы допусков M11 — их допуск (`iir`, `remez` 10⁻⁸; `firls`, `lms`, `sst_band`, `sst_ridge` 10⁻¹⁰; `cepstrum`, `time_stretch`, `pitch_shift` 10⁻⁹; `inst_freq` 10⁻⁷).
- Коммиты — короткая фраза около 5 слов, без трейлеров и без упоминаний помощника; PR — на русском, без подписи помощника.
- Ветки стопкой: `m12-version` (от `m12-spec`, переставленной на свежий `main`; несёт документ и план) → `m12-names` → `m12-vars` → `m12-py-live-1` → `m12-py-live-2` → `m12-blocks` → `m12-blocks-tui` → `m12-regions` → `m12-marks` → `m12-books` → `m12-review`. Слияние — только с согласия пользователя, по одному PR после зелёного CI.
- Сборки: clang в `scratchpad/val-rel`, GCC 16 в `scratchpad/val-gcc`; обе смотрят в `scratchpad/wt-val`, поэтому рабочее дерево M12 ставится на этот путь (`git worktree move`; ветку `strip-clip` перед этим увести на другой путь). Тесты — `../val-rel/tests/signals_tests "[тег]"` из корня дерева; мост — `python3 tools/bridge/run_scripts.py <папка>`.
- Бюджет поручений: одно поручение помощнику — не больше 400–500 тысяч токенов; проверка находок — пакетом, не по одной.

## Review Focus

1. **Файл, сохранённый наполовину.** Редактор или тест переписывает `.sig`, пока `run --watch`, предпросмотр VS Code или «Конвейер» его читают. Ожидание: пустой или обрезанный файл не выдаётся как пустой граф; прогон пропускается до следующего изменения. Сейчас 0.9.0 печатает документ с `pipeline: ""` (видно по разовому падению теста `watch json prints one document per line on stdout` на GCC). Тест в Task 3.
2. **Файл v1 с CRLF и BOM** (Windows, `core.autocrlf`). Ожидание: читается, переводится, числа те же; `migrate --write` пишет LF без BOM. Тест в Task 5.
3. **Переменная или параметр блока с именем, занятым в Python** (`let np = 4`, `let lambda = 2`, `let D = …`, `block f(print=1)`). Ожидание: живой скрипт выполняется, имя получает `_` в конце, правка этой переменной в скрипте работает. Тест в Task 12.
4. **Имя своего блока совпадает с именем узла, переменной или встроенного блока; в имени узла `/`.** Ожидание: понятная ошибка со строкой, а встроенный блок закрывается с уведомлением (§3). Тест в Task 17.
5. **Участок или метка за концом сигнала** (`region r = 5s..6s` на записи в 1 с, `mark 99s`). Ожидание: интервал обрезается по длине сигнала; полностью вне сигнала — пустой выход `take` и уведомление; метка вне графика не рисуется. Ничего не падает. Тесты в Task 24 и Task 26.
