# Signals M6a: SWT, MODWT и MRA — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** стационарные преобразования (SWT/ISWT, MODWT, MRA) в ядре, совпадающие с PyWavelets, и переключение «DWT · SWT · MODWT» на экране «Разложение».

**Architecture:**
- **Ядро** (`src/core/swt.{hpp,cpp}`): разложение без прореживания по алгоритму à trous, как `pywt.swt`, и обратное — как `pywt.iswt`. MODWT — та же схема с фильтрами, делёнными на √2 (`norm=True` в pywt). MRA — компоненты, сумма которых равна сигналу (`pywt.mra`).
- **Модель «Разложения»** получает выбор преобразования. Для SWT и MODWT все полосы длины N, поэтому подполосы, энергия и плитки считаются без растяжения.
- **Пайплайн** — блоки `swt` и `iswt`.

**Tech Stack:** как в M5b; эталоны — `tools/gen_golden.py` на PyWavelets 1.8.0.

**Spec:** `docs/03-design.md` §5 (`transform`), §7 [v1] «SWT, MODWT, MRA», §10 (эталоны), §13 строка M6.

**Решения плана (моё решение — пользователь может оспорить):**
1. **Длина сигнала.** `pywt.swt` требует N, кратное 2^J. Ядро делает так же и возвращает ошибку `level_out_of_range` с подсказкой. Модель «Разложения» дополняет сигнал периодически до кратной длины и обрезает результат: так работает любой WAV.
2. **Формат коэффициентов** — как `pywt.swt(..., trim_approx=True)`: `[cAJ, cDJ, …, cD1]`, все длины N. Тот же тип `BasicCoeffs`, что у DWT, поэтому энергия, пороги и правка полос работают без изменений.
3. **Клавиша `t`** на «Разложении» листает преобразование DWT → SWT → MODWT. Клик по названию делает то же. Пакеты и скалограмма остаются заглушками M6b.

## Global Constraints

- Всё из M5b.
- Совпадение с pywt: DWT-уровень точности (`default_tolerance`) на всех семействах из эталонов.
- Тексты — в `ru.json` и `en.json`.

## Review Focus

1. **Длина не кратна 2^J** (обычный WAV): ядро даёт понятную ошибку, а «Разложение» дополняет и обрезает, так что совершенное восстановление и энергия не страдают. Тест в Task 1 и Task 3.
2. **J = максимум для длины** (`swt_max_level`): граница совпадает с pywt. Тест в Task 1.
3. **MODWT сохраняет энергию:** Σ‖Wj‖² + ‖VJ‖² = ‖x‖² с точностью до округления. Тест в Task 1.
4. **Переключение преобразования во время расчёта** отменяет прежнюю задачу, в интерфейсе нет смеси полос двух преобразований. Тест в Task 3.
5. **Порог и правка полос на SWT** работают по тем же полосам и дают совершенное восстановление при отключённом пороге. Тест в Task 3.
