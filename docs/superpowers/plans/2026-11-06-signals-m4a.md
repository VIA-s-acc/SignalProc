# Signals M4a: звук, выделение и четыре экрана — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** В интерфейсе `signals` появляется:
- выделение мышью, которое работает в терминалах macOS;
- контекстные меню и режим прыжка;
- прослушивание сигнала;
- четыре экрана холста: «Конструктор» (3), «Объяснение» (4), «Разложение» (5) и «Матрица» (7).

**Architecture:**
- **Звук.** Новая библиотека `signals_audio` (`src/audio/`) — проигрыватель на miniaudio, §5. Устройство спрятано за интерфейсом `Sink`, поэтому тесты гоняют проигрыватель без звуковой карты, вручную.
- **Модели и экраны.** У каждого нового экрана, как в M3, модель и экран:
  - модель считает в `JobRunner` и публикует `shared_ptr<const …>`;
  - экран только рисует и принимает ввод.
- **Ядро.** Получает три функции:
  - каскадный алгоритм для φ;
  - сжатие «оставить долю коэффициентов»;
  - сингулярные числа матрицы.
- **Оболочка.**
  - вложенные вкладки: «Банк» — «Конструктор» и «Блок-схема»; «Теория» — «Объяснение», «Под капотом» и «Учебник»;
  - контекстное меню по правому клику;
  - режим прыжка `'`;
  - переход между экранами с параметрами;
  - «тикер» для анимации и бегущей позиции звука.

**Tech Stack:** как в M3, плюс miniaudio `0.11.26` (MIT-0 или public domain, один заголовок).

**Почему M4 разделён на M4a и M4b (моё решение).** Строка M4 в §13 — это пять экранов, рендерер формул, учебник и карточки «под капотом». Это два независимых куска:
- **M4a** (этот план) — звук, выделение и четыре экрана с вычислениями.
- **M4b** (`2026-11-06-signals-m4b.md`) — слой `theory`: формулы Unicode-2D, учебник, «Под капотом», карточки блоков, `F1` отовсюду.

Каждый план заканчивается рабочей программой и своим итоговым ревью. M4b опирается на M4a: вкладки «Теория», навигацию между экранами и модели экранов, которые публикуют живые числа.

**Границы M4a и решения по холсту (моё решение — пользователь может оспорить).**
1. **Прослушивание переезжает из M5 в M4a** — пользователь попросил 2026-11-06. За M5 остаются щупы конвейера с A/B.
   - В M4a: `Space` на «Сигнале» играет от курсора A или выделение, по осциллограмме бежит позиция;
   - на «Разложении» — A исходный, B Σ☑, разность, одна полоса.
2. **Выделение без `Ctrl`.** В терминалах macOS (Warp, Terminal.app) `Ctrl+клик` — это правый клик: приложение его не получает. Поэтому выделение по `Ctrl` + перетаскивание (§8.1) в M3 там не работает.
   - Решение: режим перетаскивания «сдвиг ↔ выделение» — клавиша `s` и чип в заголовке осциллограммы.
   - `Ctrl` + перетаскивание остаётся для терминалов, которые его передают.
   - `Ctrl+клик` в macOS приходит как правый клик и открывает контекстное меню, где тоже есть «курсор B здесь» и «выделить от A до B».
3. **Цифры `1…9` всегда переключают вкладки** (§8.1). На холсте они ещё и переключают полосы («1–7» на «Разложении») и шаги («1…9» на «Объяснении»). Там вместо цифр:
   - полосы: `↑↓` и `Enter`, клик по ☑ — как в макете `visualization.md` §8.3;
   - шаги: `←→` и клик по списку.
4. **`Tab` — следующая панель везде**, как в M3. «Следующее разбиение» в «Конструкторе» — `n` и `N`.
5. **«Разложение».**
   - Работают виды «Подполосы», «MRA» и «Плитки t–f» на DWT.
   - «Пакеты», «Скалограмма», SWT и MODWT — это [v1], M6. Их чипы тусклые, клик пишет, когда они появятся.
   - Нижняя панель, где на холсте скалограмма, в M4a показывает «Энергию по полосам» и «Курсор» из макета §8.3.
   - Сжатие «оставить N %» по §7.3 — [v1], но холст показывает его на этом экране, а стоит оно одну функцию ядра. Входит в M4a.
6. **«Конструктор».**
   - «Сопряжённые вместе» включено всегда: банки в ядре вещественные. Флажок виден, но не снимается.
   - `Enter` сохраняет банк в пользовательскую библиотеку файлом `.flt` (`visualization.md` §7.4в), «Фильтры» показывают его в группе «Мои фильтры».
   - Остальной редактор своих фильтров — M6.
7. **«Блок-схема»** внутри «Банка» — заглушка до M6: её нет в строке M4 §13.
8. **«Объяснение».**
   - Тексты шагов лежат в `resources/theory/explain/haar.toml` и встраиваются при сборке; правка требует пересборки.
   - Строки чисел для db2 и 5/3 считаются с продолжением нулями — как `pywt` в режиме `zero`.
   - Матрица $A_1$ строится с периодизацией: так она квадратная.
9. **«Матрица».** Числа в ячейках — когда помещаются по ширине (при 150 колонках это N ≤ 16). «N ≤ 48» с холста в 150 колонок не читается.
10. **Формулы в M4a — обычные строки Unicode** («|H₀| = √2·cos(ω/2)»). LaTeX и `F1` — в M4b, а до тех пор подсказка `F1` не показывается.

Все пути — от корня репозитория `~/GITHUB/Signals/SignalProc`. Работа идёт в ветке `m4a-screens` от `main`.

## Global Constraints

- Все ограничения M1–M3:
  - C++23, CMake ≥ 3.28, FetchContent, `double`, без `-ffast-math`;
  - только пермиссивные зависимости, лицензия MIT;
  - ошибки в `core`, `io` и `audio` — через `Result<T>`;
  - каналы по отдельности, `float` — только в буферах отображения и звука.
- Код, идентификаторы, имена тестов и сообщения разработчику — на английском. Каждая строка интерфейса — через `tr("tui.…")` с ключом в `resources/i18n/ru.json`. Тест `every tr key used in the sources exists` охватывает `src/audio` и `src/tui`.
- Комментарий — только если без него код «упростят» в ошибку.
- Интерфейс в своём потоке не считает: всё, что дороже форматирования готовых чисел, идёт через `JobRunner`.
- **Звуковой поток:**
  - не выделяет память, не делает ввод-вывод;
  - не ждёт блокировку: только `try_lock`, при неудаче пишет тишину;
  - устройство никогда не останавливается из колбэка.
- **Перерисовка.** По событиям рабочих потоков, звука и анимации — не чаще 30 раз в секунду. Тикер работает, только пока что-то играет или анимируется: в покое CPU остаётся как в M3, меньше 1 %.
- **Клавиши:**
  - `1…9` — вкладки;
  - `Tab`/`Shift+Tab` — панели;
  - `[`/`]` — вложенные вкладки;
  - `'` — прыжок;
  - правый клик — меню;
  - `Space` — играть или остановить (там, где есть звук);
  - `Esc` сначала останавливает звук, потом прерывает задачу.
- **Цвета (§8.2):**
  - h₀ — `trace[0]`, h₁ — `trace[1]`;
  - F₀ и f₀ в «Конструкторе» — оттенок h₀: `tint(trace[0], fg, 0.5)`, полые маркеры ○ и пунктир;
  - знаковые матрицы — дивергентная шкала: + цветом h₀, − цветом h₁, 0 — фоном;
  - подсветка — `accent`.
- Каждое ✓ на экране — результат вычисления с порогом, иначе «—» или ✗ (§2, анти-цели).
- Числа на экране — `format_number` и `format_si` из M3: запятая, минус `−`, `3,1·10⁻¹⁶`.
- Снимочные тесты — на 150×44 и 80×24. Задачи в тестах синхронные (`JobRunner` в режиме `inline`), звук — через `ManualSink`, время — через подставные часы.
- В тестах нет терминала, звукового устройства и `App::Loop`.
- Перед финалом:
  - сборки GCC 16 — Release с `-Werror` и ASan с `-fno-range-for-ext-temps`;
  - TSan на тестах `[audio]` и `[jobs]`.
- Каждый новый файл данных (`haar.toml`, снимки) проверяется командой `git status --ignored`.
- Коммит — короткое предложение (~5 слов), без `Co-Authored-By`.

```cpp
struct Clip {
    std::vector<std::span<const float>> channels;  // equal lengths
    std::uint32_t rate = 0;
    std::shared_ptr<const void> owner;             // keeps the spans alive
    std::string tag;                               // who plays: "signal", "decomposition.b", ...
    std::size_t frames() const;
};
class Sink {
public:
    using Pull = std::function<void(float* interleaved, std::size_t frames)>;
    virtual ~Sink() = default;
    virtual core::Result<void> start(std::uint32_t rate, std::uint32_t channels, Pull pull) = 0;
    virtual void stop() = 0;
};
core::Result<std::unique_ptr<Sink>> make_device_sink();
enum class PlayState { stopped, playing, finished, unavailable };
class Player {
public:
    explicit Player(core::Result<std::unique_ptr<Sink>> sink);
    ~Player();
    core::Result<void> play(Clip clip, std::size_t from, std::optional<std::size_t> to = std::nullopt);
    void replace(Clip clip);   // A/B: keeps the position, clamps it to the new length
    void stop();
    void poll();               // UI thread: after the end, stops the sink and moves to finished
    PlayState state() const;
    std::size_t position() const;
    std::string tag() const;
    std::optional<std::string> unavailable_reason() const;
};
```

**Interfaces:**
- Produces (`signals::core`):
  - `struct Cascade { std::vector<double> phi; double dt = 1; double support = 0; double norm_ratio = 0; };`
  - `Result<Cascade> cascade(const Laurent& h, int iterations);`
    - Алгоритм — `#wav-cascade` и холст: $c = 2h/\sum h$, $\varphi^{(0)}=[1]$, $\varphi^{(i+1)}=(\uparrow2\,\varphi^{(i)})*c$.
    - $n_i=\sqrt{\sum(\varphi^{(i)})^2/2^i}$, `norm_ratio` $=n_I/n_{I-1}$.
    - `dt` $=2^{-I}$, `support` $=L-1$.
    - `invalid_argument`, если $\sum h=0$ или `iterations < 2`.
  - `std::size_t keep_largest(std::vector<std::vector<double>>& bands, double fraction, std::size_t first_band = 1);`
    - в полосах с `first_band` по последнюю оставляет $\lceil\text{fraction}\cdot\text{всего}\rceil$ коэффициентов с наибольшим $|c|$, остальные обнуляет;
    - возвращает число оставленных; при равенстве $|c|$ оставляет более ранние.
  - `std::vector<double> singular_values(const Eigen::MatrixXd& a);` — по убыванию, `JacobiSVD`.
  - `double condition_number(std::span<const double> singular);` — $\sigma_{\max}/\sigma_{\min}$, ∞ при $\sigma_{\min}=0$.

```cpp
enum class RowOrder { blocks, interleaved };
struct MatrixOptions {
    std::string wavelet = "db2";
    MatrixOp op = MatrixOp::analysis;
    core::Extension mode = core::Extension::periodization;
    RowOrder order = RowOrder::blocks;
    std::size_t n = 32;                 // even, [2, 256]
    std::size_t levels = 3;
    bool gram = false;                  // t: show MᵀM
};
struct RowTerm { double coef; std::size_t column; double x; double product; };
struct MatrixData {
    MatrixOptions options;
    Eigen::MatrixXd m;                  // what is drawn (MᵀM when gram)
    std::vector<std::string> row_names; // L₀…, B₀… or a₀, d₀, a₁… or a₃[0]…
    std::vector<std::string> outputs;   // a₅, d₀, y₇ …
    std::size_t detail_start = 0;       // first B row in block order
    std::vector<double> x, y;           // x[n] = round(8 sin(2πn/16) + n/2), y = M x
    std::optional<double> orth_error, transpose_error, left_inverse_error;
    std::vector<double> singular;
    double cond = 0;
    bool square = true;
    std::optional<std::string> error;   // core error text; checks show it instead of numbers
    Eigen::MatrixXd toeplitz;           // T(h0), 12 × 12, rows r, cols c: h0[r − c]
};
class MatrixModel {
public:

    MatrixOptions options() const;
    std::shared_ptr<const MatrixData> data() const;
    std::vector<RowTerm> row_terms(std::size_t row) const;
};
```
