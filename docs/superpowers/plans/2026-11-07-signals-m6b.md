# Signals M6b: пакеты вейвлетов, лучший базис и скалограмма CWT — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** пакеты вейвлетов с лучшим базисом и CWT в ядре, совпадающие с PyWavelets, и виды «Пакеты» и «Скалограмма» на экране «Разложение» вместо заглушек.

**Architecture:**
- **Ядро.** `src/core/packets.{hpp,cpp}` — полное дерево пакетов, как `pywt.WaveletPacket`, восстановление из любого допустимого базиса, лучший базис Койфмана–Викерхаузера. `src/core/cwt.{hpp,cpp}` — CWT по алгоритму `pywt.cwt`, свёртка через FFT (pocketfft) и потоковый расчёт по масштабам.
- **Модель «Разложения»** считает пакеты и скалограмму отдельными задачами и только когда открыт их вид. Вид «Подполосы» от этого не замедляется.
- **Экран.** «Пакеты» — таблица узлов: уровни сверху вниз, узлы в частотном порядке. Цвет показывает энергию, базис выделен, клик по узлу делает его листом базиса. «Скалограмма» — тепловая карта |W(a, t)| в дБ (viridis, пол −48 дБ, ось частот логарифмическая, конус влияния затенён).

**Tech Stack:** как в M6a; эталоны — `tools/gen_golden.py` на PyWavelets 1.8.0.

**Spec:** `docs/03-design.md` §5 (`transform`), §7 [v1] «пакеты и лучший базис, CWT», §10 (эталоны), §13 строка M6; теория `docs/02-theory.md` §8.8, §11.3, §11.6; холст `docs/design/Decomposition.dc.html` (панель «Скалограмма · CWT Морле · |W(a, t)|, дБ», «viridis · пол −48 дБ · ось частот лог.»).

**Решения плана (моё решение — пользователь может оспорить):**
1. **Блоков конвейера для пакетов и CWT нет.** Их выход не укладывается в `Coeffs` с полосами `a, dJ…d1`. Нужен новый тип порта, и это отдельная работа.
2. **Пакеты строятся на прореженном DWT** в выбранном режиме краёв. Чипы SWT/MODWT на виде «Пакеты» приглушены. Клик по ним объясняет, что пакеты бывают только прореженными.
3. **Скалограмма — Морле `morl`, 8 голосов на октаву.** Частоты идут от `max(20 Гц, 16·fc·fs/N)` до `0,4·fs`; в последней формуле `fc` — центральная частота вейвлета при масштабе 1. Если N > 2^20, сигнал сначала прореживается в целое число раз до N ≤ 2^20: тогда верх шкалы — 0,4 от новой частоты. Подзаголовок панели сообщает об этом.
4. **Стоимость лучшего базиса — энтропия Шеннона** $-\sum p\log p$ с $p=c^2/\|x\|^2$. Лог-энергия доступна в ядре, на экран не выносится.

## Global Constraints

- Всё из M6a.
- Совпадение с pywt: узлы пакетов — с точностью `default_tolerance`. CWT — относительная ошибка ≤ 1e-9 от max|W| по масштабу (эталон `method='conv'`, у нас FFT).
- Тексты — в `ru.json` и `en.json`.
- Скалограмма `test.wav` в release считается не дольше 1,5 с, память на расчёт — O(N + строки·столбцы).

## Review Focus

1. **Узел длиннее сигнала** (`J` больше `dwt_max_level`, короткий WAV): ядро не падает; `wp_decompose` ведёт себя как pywt с явным `maxlevel`. Тест в Task 1.
2. **Нечётные длины узлов:** восстановление из любого допустимого базиса обрезает узел до длины родителя, как pywt. Совершенное восстановление на N = 77. Тест в Task 1.
3. **Очень маленький и очень большой масштаб CWT:** `scale·16 + 1 < 2` даёт ошибку `invalid_argument`, а не мусор. Масштаб с ядром длиннее сигнала совпадает с pywt. Тест в Task 2.
4. **Смена вейвлета, J или файла во время расчёта скалограммы** отменяет задачу: на экране не бывает смеси старой и новой карт. Тест в Task 4.
5. **Узкий терминал 80×24 и J = 12:** у таблицы пакетов больше узлов, чем столбцов; столбец показывает максимум энергии своих узлов, клик попадает в узел под курсором. Тест в Task 3.

### Task 2: CWT в ядре

**Files:** create `src/core/cwt.{hpp,cpp}`, `tests/core/test_cwt.cpp`, `tests/golden/cwt.json`; modify `tools/gen_golden.py`, CMake.

**Interfaces — Produces:**

```cpp
struct ContinuousWavelet {
    enum class Family { morl, mexh, cmor } family = Family::morl;
    double bandwidth = 1.5, center = 1.0;   // только cmor
    bool complex() const;
    double lower() const, upper() const;    // morl, mexh, cmor: −8 … 8
};
Result<ContinuousWavelet> continuous_wavelet(std::string_view name);   // "morl", "mexh", "cmor1.5-1.0"
double center_frequency(const ContinuousWavelet& w, int precision = 12);   // pywt.scale2frequency(w, 1, precision)
using CwtRow = std::function<void(std::size_t scale_index, std::span<const std::complex<double>> row)>;
Result<void> cwt_rows(std::span<const double> x, std::span<const double> scales, const ContinuousWavelet& w, const CwtRow& out, ProgressSink* p = nullptr);
Result<std::vector<std::vector<std::complex<double>>>> cwt(std::span<const double> x, std::span<const double> scales, const ContinuousWavelet& w, ProgressSink* p = nullptr);
```

Алгоритм — дословно `pywt.cwt` при `precision = 12`: `wavefun` на `linspace(lower, upper, 2^12)`, `int_psi = cumsum(psi)·step`, для complex — сопряжение, выборка `j = floor(arange(ceil(s·(x₋₁−x₀)+1)) / (s·step))`. Затем свёртка, `−√s·diff`, обрезка `floor(d)…−ceil(d)`. Свёртка через FFT общего размера `next_pow2(N + L_max − 1)`: FFT сигнала считается один раз на все масштабы. Отмена — `stop_requested` между масштабами.

- [ ] **Step 1: golden** — `pywt.cwt(x, scales, w, method='conv')` и `pywt.scale2frequency(w, 1, 12)` для morl, mexh, cmor1.5-1.0; N = 100 и 257; масштабы `[0.5, 1, 2.5, 8, 40]` (40 — ядро длиннее сигнала).
- [ ] **Step 2: failing tests** — совпадение с эталоном до 1e-9·max|W|; `cwt_rows` выдаёт строки по порядку и столько же, сколько масштабов; масштаб 0,05 — ошибка `invalid_argument`; отмена через `CancelToken` останавливает расчёт до последнего масштаба.
