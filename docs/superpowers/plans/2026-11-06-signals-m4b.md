# Signals M4b: теория — формулы, учебник, «Под капотом», карточки — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** У каждого метода открывается теория. Для этого:
- `F1` с любого экрана открывает карточку блока: формулы, стоимость, те же формулы с живыми числами, проверки с текущими ошибками, связи, переход к визуализации, исходник и тест;
- «Учебник» показывает `02-theory.md` по разделам, с поиском и ссылками;
- формулы рисуются своим рендерером Unicode-2D подмножества LaTeX;
- для каждого блока [ядро] есть карточка, и тест сборки это проверяет.

**Architecture:**
- **Слой `theory`.** Новая библиотека `signals_theory` (`src/theory/`), §5. Зависит только от `signals_core` и toml++, про FTXUI не знает. В ней:
  - `02-theory.md` и карточки, встроенные при сборке;
  - разбор разделов по `{#id}`;
  - разбор подмножества LaTeX в дерево;
  - раскладка дерева в прямоугольник строк Unicode или ASCII с базовой линией — модель боксов TeX, образец — sympy `prettyForm`;
  - разбор Markdown в блоки;
  - реестр живых значений и подстановка `{{…}}`;
  - каталог блоков.
- **TUI.**
  - виджет документа рисует блоки Markdown с формулами;
  - навигатор теории общий для вложенных вкладок «Под капотом» и «Учебник»;
  - каждый экран сообщает, какой блок у него в фокусе, и публикует его живые значения.
- **Живые числа.** Открытая по `F1` карточка держит слабую ссылку на экран-источник и перечитывает его значения на каждом кадре. Когда источник меняется, числа идут за ним. Когда экрана больше нет, остаётся последний снимок.

**Tech Stack:** как в M4a. Новых зависимостей нет.

**Spec:** `docs/03-design.md`:
- §5 — слой `theory`;
- §8.6 — карточки, учебник, реестр живых значений, тест сборки, формулы;
- §10 — каждое ✓ вычислено;
- §13, строка M4.

Образец экрана — `docs/design/Theory.dc.html` (холст, экран 8). Поведение, которого на холсте нет, — `docs/research/visualization.md`:
- §6.1 — рендерер;
- §7.13 — «Под капотом» и «Учебник»;
- §8.6 — макет.

**Опирается на M4a:** вложенные вкладки, `UiContext::navigate`, контекстные меню, модели экранов.

**Границы M4b и решения (моё решение — пользователь может оспорить).**
1. **Формулы — Unicode-2D и ASCII**, выбор `auto | unicode | ascii` и клавиша `g`. Пиксельный маршрут (kitty, sixel) — M7, §13.
2. **Строчные формулы `$…$` — в одну строку.** `\frac{a}{b}` → `a/b`, `\tfrac12` → `½`, индексы — символами Unicode. Двумерно рисуются только выключные `$$…$$`. Иначе абзац с дробью рвётся на три строки.
3. **Карточки** — `resources/theory/blocks/<id>.md`:
   - заголовок TOML между `+++`;
   - разделы в порядке §8.6.
   - Пункт 7 («переход к визуализации») и пункт 8 («исходник и тест») берутся из заголовка, а код в разделе «Реализация» тест сверяет с исходником дословно.
4. **Каталог блоков** — список в C++ (`theory::block_catalog()`): id, ярус, раздел теории, публикуемые значения. В M5 его заменят типы узлов конвейера. Сейчас это единственный независимый список, по которому тест проверяет «у каждого блока есть карточка».
5. **Блоки [ядро]** — 29 карточек: проектирование и анализ, преобразования, обработка, ввод-вывод и поэлементные операции. Лифтинг, L/M, SWT, CWT, Уэлч — [v1], их карточки в M6.
6. **`F1` на «Объяснении» открывает «Учебник» на §5 `{#haar}`**, как подписано на холсте, а не карточку.
7. **`o` открывает исходник** в `$VISUAL` или `$EDITOR` через `App::WithRestoredIO`. Без них:
   - macOS — `open -t`;
   - Linux — `xdg-open`.
8. **Копирование формулы** — пункт контекстного меню «Копировать LaTeX», OSC 52.
9. **`n` сворачивает и разворачивает «С числами этого блока»** (на холсте — «n с числами»).

Все пути — от корня репозитория. Работа идёт в ветке `m4b-theory` от `main` после слияния M4a.

## Global Constraints

- Все ограничения M4a.
- `signals_theory` не зависит от `signals_tui`, FTXUI и потоков интерфейса.
- `02-theory.md` правится только ради исправлений (§8.6). Если формула оттуда не разбирается, расширяется рендерер, а не книга.
- Карточки и тексты учебника — на русском, это содержимое. Код, имена тестов и сообщения разработчику — на английском.
- **Живые значения:**
  - нет значения — «—»;
  - проверка без данных — «— нет данных» и никогда не ✓.
  - Числа форматирует экран-публикатор (`format_number`); слой `theory` получает готовые строки и `CheckResult`.
- **Формулы:**
  - все строки бокса одной ширины в колонках, комбинирующие знаки — нулевой ширины;
  - формула, которую не удалось разобрать, показывается исходником тусклым цветом с пометкой и не роняет экран.
- Встроенные тексты — через `signals_embed_text`. Изменение `.md` пересобирает цель: `CONFIGURE_DEPENDS` на каталог карточек.
- Снимочные тесты — на 150×44 и 80×24.

## Review Focus

1. **Формула, которую рендерер не знает,** — в карточке, исправленной руками, или в будущей правке книги. Ожидается исходник тусклым цветом и строка «формула не разобрана: \\foo», без падения. Тест линтера ловит такие случаи в репозитории. Тест в Task 3 и 6.
2. **Узкий терминал** (80×24) и широкие формулы и таблицы. Ожидается обрезка с `…` справа и прокрутка по горизонтали `←→` в документе. Ни одна строка не вылезает за панель. Тест в Task 6.
3. **Карточка без живого контекста** (открыта из оглавления или каталога). Все плейсхолдеры «—», проверки «— нет данных», ни одного ✓. Тест в Task 8.
4. **Источник изменился или исчез после `F1`.**
   - Сменили вейвлет на «Разложении» — числа в карточке следуют.
   - Вкладку пересоздали — показывается снимок с пометкой «снимок».
   - Тест в Task 9.
5. **Поиск:**
   - кириллица в любом регистре, «ё» и «е»;
   - символы «P₀», «↓2»;
   - пустой запрос и запрос без совпадений — «0 из 132».
   - Без падений, выделение не выходит за список. Тест в Task 1 и 7.

### Task 3: раскладка формул — Unicode-2D, ASCII, в строку

**Files:**
- Create: `src/theory/math_layout.{hpp,cpp}`, `tests/theory/test_math_layout.cpp`

**Interfaces:**
- Produces (`signals::theory`):
  - `enum class MathStyle { display, inline_linear };`
  - `enum class MathGlyphs { unicode, ascii };`
  - `struct MathBox { std::vector<std::string> lines; int baseline = 0; int width = 0; };`
  - `MathBox layout(const MathNode& node, MathStyle style, MathGlyphs glyphs);`
  - `std::expected<MathBox, LatexError> render_latex(std::string_view src, MathStyle style, MathGlyphs glyphs);`
- **Правила display:**
  - дробь — числитель, черта `─` шириной max+2, знаменатель, по центру, базовая линия — на черте;
  - индексы — символами Unicode, если у всех знаков есть формы `⁰¹²³⁴⁵⁶⁷⁸⁹⁺⁻⁼⁽⁾ⁱⁿ…` и `₀…₉₊₋₌₍₎ₐₑₒₓₕₖₗₘₙₚₛₜᵢⱼ`; иначе бокс сдвигается на строку вверх или вниз;
  - `∑ ∏ ∫` с пределами сверху и снизу, по центру;
  - `√` — для однострочного подкоренного `√2` или `√(x² + 1)`, для многострочного — `╲╱` с чертой сверху;
  - растущие скобки `⎛⎜⎝ ⎞⎟⎠ ⎡⎢⎣ ⎤⎥⎦ ⎧⎨⎩`, однострочные — `( ) [ ] { }`;
  - матрица — сетка с выравниванием по центру и двумя пробелами между столбцами;
  - акцент над одним знаком — комбинирующий символ (U+0302, U+0303, U+0304), над группой — строка `‾`;
  - бинарные операции и отношения — по пробелу с каждой стороны; `\quad` — 2 пробела, `\qquad` — 4, `\,` — 1.
- **`inline_linear`:**
  - одна строка;
  - `\frac{a}{b}` → `a/b`, сложные части в скобках;
  - простые дроби → `½ ⅓ ¼ ⅕ ⅙ ⅛ ⅔ ¾`;
  - пределы большого оператора — нижним и верхним индексом.
- **ASCII:**
  - греческие — именами (`omega`, `pi`);
  - `<=`, `>=`, `!=`, `->`, `<=>`, `+-`, `x`, `*`;
  - черта дроби `-`, скобки `/ | \`, `sum`, `prod`, `int`, `sqrt(...)`;
  - индексы всегда `_` и `^` в строку.

### Task 4: модель Markdown

**Files:**

struct Inline {
    enum class Kind { text, strong, emphasis, code, math, ref, placeholder };
    Kind kind = Kind::text;
    std::string text;               // math: LaTeX source; placeholder: name; ref: label shown
    std::string target;             // ref: section id
    std::vector<Inline> children;   // strong / emphasis
};
struct Block {
    enum class Kind { heading, paragraph, bullet, numbered, table, display_math, code, rule };
    Kind kind = Kind::paragraph;
    int level = 0;                  // heading level; list nesting
    int number = 0;                 // numbered list item
    std::vector<Inline> inlines;
    std::vector<std::vector<std::vector<Inline>>> table;   // rows → cells → inlines, first row = header
    std::string text;               // display_math source, code body
    std::string language;           // code fence language
};
std::vector<Block> parse_markdown(std::string_view md);
std::vector<std::string> math_spans(std::string_view md);   // also used by tests and the card linter
