# Signals M9: учебный путь — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** встроенный курс из 66 заданий с автопроверкой: движок `src/learn/`, команда `signals learn`, вкладка «Теория ▸ Задания» и строка задания на всех вкладках.

**Architecture:**
- **Модули.**
  - Выражения — `src/core/expr.*`. Модуль общий: позже его возьмут блок `assert` и параметры конвейера.
  - Движок — `src/learn/`, библиотека `signals_learn` поверх `signals_pipeline` и `signals_theory`: формат задания, варианты, измерения, структурные условия, проверяющий, прогресс, отчёт, проверка курса.
- **Как идёт проверка.**
  - Проверяющий копирует документ `.sig` студента и добавляет щупы `__learn:<узел.порт>` на всё, что измеряет.
  - Прогоняет граф тем же `run_graph`, что и `signals run`, и считает измерения сам.
  - Повторяет прогон на скрытых входах.
- **Где используется.**
  - Встроенный курс зашит в программу.
  - CLI (`src/commands/learn_commands.cpp`) и интерфейс (`src/tui/data/learn_state.*`, `src/tui/screens/learn_screen.*`) зовут один и тот же `check_task`.

**Tech Stack:** C++23, toml++ (уже в проекте), Catch2, существующий исполнитель конвейера.

**Spec:** `docs/superpowers/specs/2026-11-13-signals-m9-learning-path-design.md`.

**Решения плана (мои, пользователь может оспорить):**
1. Выражения живут в `core`, а не в `learn`: иначе блок `assert` в `pipeline` получил бы зависимость по кругу.
2. Папка настроек (`$XDG_CONFIG_HOME/signals`, `%APPDATA%\signals`, `~/.config/signals`) переезжает из `tui/term/caps.cpp` в `src/io/config_dir.*`: CLI не связан с `signals_tui`.
3. Тексты целей лежат в `ru.md`/`en.md` разделом `## Цели {#goals}` (нумерованный список в порядке `[[goal]]`), а не в TOML: так у каждого языка свой текст.
4. Ответ-выбор с вычисляемым правильным вариантом: автор пишет номер варианта в `expected`, а `verify` — выражение над измерениями эталонного решения, которое тест курса проверяет.
5. Задания не ссылаются на внешние звуковые файлы: источники — `samples` и `gen` (с `add_noise`). Тогда граф задания можно прогнать из любого каталога.
6. Скрытые входы — только у источника `samples`: новые отсчёты того же числа, нормальные с зерном `(задание, вариант, k)`, шесть знаков.
7. Нормальный шум для вариантов — сумма 12 равномерных минус 6 (без `std::*_distribution` и `libm`): числа одинаковы на всех платформах.
8. `--progress FILE` у всех `signals learn …`: тесты и преподаватель работают с чужим файлом прогресса.
9. Строка задания появляется в оболочке только при активном задании, поэтому существующие снимки экранов не меняются.
10. Время одной проверки ограничено 30 с; дольше — ошибка «проверка дольше 30 с».

## Global Constraints

- Комментарии в коде — только там, где без них код сломают; всё в коде по-английски, тексты интерфейса — через `resources/i18n/ru.json` и `en.json` с одинаковыми ключами (тест `tests/test_i18n_keys.cpp`).
- Перед пушем — сборка с `-DSIGNALS_WERROR=ON` на clang и на GCC 16 с `-fno-range-for-ext-temps`; на Windows нельзя называть переменные `near`, `far`.
- Каждый экран: `Tab` по панелям, `z` на весь экран, листание списков с «▲/▼ ещё N», узкая раскладка на 80×24, без молчаливой обрезки (общий тест «всё помещается»).
- Возможность доходит до интерфейса, CLI, отчёта, «Учебника» и документации; пропуски называются в PR.
- Коммиты — короткая фраза в 5 слов, без приписок; PR без упоминания инструментов.
- Номер задания `глава.задание` берётся из префиксов каталогов `NN-…`; варианты 1…999, по умолчанию 1.
- Коды выхода `signals learn check`: 0 — засчитано, 3 — цели не выполнены, 1 — ошибка задания или графа, 2 — ошибка вызова.

## Review Focus

1. Граф студента не собирается (нет узла, не тот тип порта, цикл): проверка возвращает понятную ошибку со строкой, цели показаны как «·», ничего не падает. Тест в задаче 7.
2. Студент удалил или переименовал узел-источник `x`: проверка не пропускает скрытые входы молча, а пишет «узел x из заготовки удалён». Тест в задаче 7.
3. Испорченный или чужой `learn.toml`: программа запускается, старый файл сохраняется как `learn.toml.bak`, прогресс начинается заново с уведомлением. Тест в задаче 8.
4. Ответ с другим числом элементов, со скобками `[1, 2]`, с выражениями `sqrt(2)/2`: скобки и запятые принимаются, неверная длина даёт «нужно 5 чисел, введено 6». Тест в задаче 6.
5. Граф студента считается очень долго (свип на час): автопроверка отменяется `Esc` и ограничена 30 с. Тест в задаче 7: отменённый `CancelToken` и ограничение в 0,01 с на тяжёлом графе.
