# Signals M5b: редактор конвейера — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** вкладка «8 Конвейер» собирает, правит, запускает и сохраняет граф `.sig` мышью и клавиатурой; `denoise.sig`, собранный в TUI, даёт те же отсчёты, что через CLI.

**Architecture:**
- **Модель редактора** `PipelineModel` (`src/tui/screens/pipeline_model.*`) держит `PipelineDoc`, снимки для отмены, путь и признак «изменён», выделение, результат проверки графа и состояние последнего запуска. Правки идут только через неё; каждая правка — новый снимок документа.
- **Запуск** — задача `JobRunner` вызывает `pipeline::run_graph` M5a с общим `ResultCache` (четверть физической памяти). События узлов копируются в модель под мьютексом, интерфейс читает снимок.
- **Раскладка** — общий для CLI и TUI расчёт слоёв и порядка (`pipeline::layout_graph`). TUI ставит слои столбцами слева направо, CLI рисует текст сверху вниз, как в M5a.
- **Экран** `PipelineScreen` (`src/tui/screens/pipeline_screen.*`) — панели холста `docs/design/Pipeline.dc.html`: граф, добавление блока, инспектор, щуп, текст `.sig`, запуск.

**Tech Stack:** как в M5a (C++23, FTXUI 7.0.3, Taskflow 4.1.0, Catch2, toml++, fmt).

**Spec:** `docs/03-design.md`:
- §8.7 «Редактор конвейера» — типизированные порты, авто-раскладка Сугиямы, вставка блока в провод, обход блока, щуп на любом проводе, отмена через снимки;
- §8.4 — этапы в рамках узлов;
- §8.8 — время CPU, настенное время, память и попадание в кэш у каждого узла, узкое место подсвечено;
- §13 строка M5b;
- холст `docs/design/Pipeline.dc.html`.

**Решения плана (моё решение, пользователь может оспорить):**
1. **Направление.** Граф на экране идёт слева направо (слой — столбец): на 150×44 помещается шесть слоёв по 20 колонок. CLI остаётся сверху вниз.
2. **Обход блока** хранится в `.sig` словом `bypass` после скобок: `node thr = threshold(mode=soft) bypass`. Обойти можно блок, у которого первый вход и первый выход одного типа: значение проходит насквозь, а состояние узла — `bypassed`.
3. **Щуп из интерфейса** — `probe` на выходе узла или на полосе. Имя по умолчанию — `узел.порт`.
4. **Открытие другого `.sig`** не спрашивает подтверждения: прежний документ остаётся снимком отмены (`Ctrl+Z` возвращает его).
5. **A/B на щупах:** A — вход графа (первый источник `wav`), B — выбранный щуп. Оба играют через `ui.player` с общей позицией, как на «Разложении».
6. **Спектрограмма щупа** не входит в M5b: она принадлежит экрану «Спектр» (M6). Щуп показывает время и спектр.

## Global Constraints

- Все ограничения M4b и M5a.
- Тексты интерфейса — только через словарь, ключи добавляются и в `ru.json`, и в `en.json` (тест покрытия словаря должен оставаться зелёным); в английском режиме на экране нет кириллицы.
- Всё управляется с клавиатуры; у каждого действия мышью есть клавиша, и она есть в справке `?`.
- Кадр 150×44 — меньше 16 мс (§11).
- Снимочные тесты для 150×44 и 80×24 через `tests/tui/harness.hpp`; `SIGNALS_UPDATE_SNAPSHOTS=1` их обновляет.
- `signals_pipeline` по-прежнему не зависит от TUI.

## Review Focus

1. **Правка во время запуска** (изменили параметр или удалили узел, пока граф считается): запуск доводит свой снимок до конца, его результаты относятся к узлам по имени, удалённые узлы просто пропадают из состояний, ничего не падает. Тест в Task 4.
2. **«Сохранить как» в другой каталог:** относительные пути `wav` и `wav_out` переписываются относительно нового места, файл открывается из CLI и даёт тот же результат. Тест в Task 3.
3. **Соединение, дающее цикл или несовместимый тип,** отклоняется с понятной причиной, документ и снимки отмены не меняются. Тест в Task 3.
4. **Большой граф или узкое окно** (40 узлов, 80×24): граф листается и показывает «◂ ▸ ещё», выбранный узел всегда в окне. Тест в Task 5.
5. **Ошибка блока посреди запуска** (нет файла, неверный уровень полосы): узел красный с сообщением в инспекторе, потомки «обход», правка и повторный запуск работают. Тест в Task 4.

struct Selection { enum class Kind { none, node, wire } kind = Kind::none; std::string node; pipeline::Edge wire; };
class PipelineModel {
public:
    const pipeline::PipelineDoc& doc() const;

    bool dirty() const;
    std::optional<pipeline::SigError> problem() const;                  // ошибка build_graph текущего документа
