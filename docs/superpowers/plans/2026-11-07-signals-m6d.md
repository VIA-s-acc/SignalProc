# Signals M6d: экран «Обработка» и правила SURE, Minimax — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** вкладка «7 Обработка» по холсту `Processing.dc.html` и правила порога SURE и Minimax в ядре:
- шумоподавление фрагмента с эталоном без шума;
- коэффициенты с ±λⱼ;
- сигнал A/B/X;
- кривая сжатия;
- правка полос с T(ω) и наложением A(ω);
- итог SNR.

**Architecture:**
- **Ядро** (`src/core/process/shrink.{hpp,cpp}`):
  - `ShrinkRule::sure` — SureShrink по уровню (Донохо–Джонстон 1995), с гибридным переходом на универсальный порог для разреженных полос;
  - `ShrinkRule::minimax` — λ = σ·(0,3936 + 0,1829·log₂N) при N > 32, иначе 0.
  - Оба правила доступны в блоке конвейера `threshold` и на «Разложении».
- **Модель** `ProcessingModel` (`src/tui/screens/processing_model.{hpp,cpp}`):
  - фрагмент открытого файла (по умолчанию 8192 отсчёта с 100 000, канал L — как на холсте) или выделение «Сигнала»;
  - шум с заданным SNR (по умолчанию 10 дБ) от детерминированного генератора;
  - разложение, пороги, восстановление, остаток, SNR вход/выход, MSE, сохранённые коэффициенты, кривая ошибки от K;
  - T(ω) и A(ω) для усилений полос — по методу `gen_screens.py` (синусы, периодизация, БПФ).
- **Экран** `ProcessingScreen` (`src/tui/screens/processing_screen.{hpp,cpp}`) — раскладка, тексты и клавиши по холсту.

**Tech Stack:** как в M6c.

**Spec:** `docs/03-design.md` §7.3 [v1] «Правила SURE, Bayes, Minimax; сжатие», §8; `docs/02-theory.md` §12.1; холст `docs/design/Processing.dc.html`, данные `docs/design/processing.json`, генератор `docs/design/gen_screens.py` (алгоритмы порогов, сжатия, T(ω) и A(ω) — оттуда).

**Решения плана (моё решение — пользователь может оспорить):**
1. **Шум.** Шум холста (numpy `default_rng(7)`) в C++ не воспроизвести. Экран использует свой генератор с зерном 7. Тесты сверяют алгоритмы на зашумлённом сигнале, записанном в эталон из Python.
2. **SURE** — как в `wavelet toolbox`/WaveLab `ThreshSURE`:
   - λ минимизирует `N − 2·#{|c| ≤ λ} + Σ min(c², λ²)` по кандидатам |c| в шкале σ = 1;
   - гибрид: если `(‖c‖²/σ² − N)/N ≤ (log₂N)^{3/2}/√N`, берётся универсальный порог.
3. **Ссылка «7 Обраб. →»** с «Разложения» открывает этот экран с теми же вейвлетом и J.

## Global Constraints

- Всё из M6c.
- Bayes, Visu, soft/hard и кривая сжатия на эталонном шумном сигнале совпадают с `processing.json`: SNR ±0,01 дБ, `kept` точно, `err_db` ±0,01.
- T(ω) и A(ω) пресетов совпадают с `processing.json` до 0,05 дБ.
- Тексты — в `ru.json` и `en.json`; карточка «Под капотом» `threshold` получает SURE и Minimax.

## Review Focus

1. **Фрагмент короче 2^J·L** или файл короче 8192: экран сообщает и предлагает меньшее J, без падения.
2. **σ = 0** (тишина): λ = 0, SNR выхода не NaN, кривая сжатия без деления на ноль.
3. **SURE на очень разреженной полосе** уходит в универсальный порог; на плотной — даёт λ меньше универсального.
4. **Смена файла и параметров во время расчёта** отменяет задачу и не смешивает результаты.
5. **Усиление полосы 0 и +20 дБ:** наложение A(ω) растёт и показывается, T(ω) не теряет точности.
