# Обзор вейвлет-ПО и банков фильтров: чек-лист функций для C++ тулкита

Дата обзора: 2026-11-05. Цель: опереться на то, что реально есть в существующих
инструментах, и выбрать полезное для аудио (двухканальные PR-банки фильтров из

## 0. Метод и степень достоверности

Метки в тексте:

- **(проверено)** — проверено запуском локального PyWavelets **1.8.0** (Python 3.13,

- **(не проверено)** — не удалось подтвердить; использовать только как гипотезу.

## 2. Соглашения о фильтрах (точные формулы)

Всё ниже **проверено** на 106 дискретных вейвлетах PyWavelets 1.8.0 (ошибки ≤ 1e-15,
если не оговорено), кроме мест с пометкой.

### 2.1 Четыре фильтра

`Wavelet.filter_bank = [dec_lo, dec_hi, rec_lo, rec_hi]` (док.), длина каждого `n` (у
биортогональных более короткие фильтры дополняются нулями: у `bior3.5` в `rec_lo` по 4
нуля с каждого края).

Пусть `h` — «стандартный» масштабирующий фильтр Добеши (для db3
`[0.3327, 0.8069, 0.4599, -0.1350, -0.0854, 0.0352]`). Тогда в PyWavelets:

```
rec_lo = h
dec_lo = h[::-1]                      (ортогональный случай: rec_lo = dec_lo[::-1])
rec_hi[k] = (-1)^k       * dec_lo[k]          k = 0 .. n-1
dec_hi[k] = (-1)^(k+1)   * rec_lo[k]
```

Для ортогональных вейвлетов это то же самое, что

```
dec_hi[k] = (-1)^(k+1) * dec_lo[n-1-k]
rec_hi    = qmf(rec_lo),   qmf(f)[k] = (-1)^k * f[n-1-k]
inverse_filter_bank = [rec_lo[::-1], rec_hi[::-1], dec_lo[::-1], dec_hi[::-1]]   (док.)
```

Формулы `rec_hi[k] = (-1)^k dec_lo[k]` и `dec_hi[k] = (-1)^(k+1) rec_lo[k]` выполняются
и для биортогональных (проверено на всех 106). `dec_hi == qmf(dec_lo)` **неверно**
(проверено): `qmf` нужно применять к `rec_lo`, а не к `dec_lo`. Это типичная ошибка при
переносе.

Нормировка: `sum(dec_lo) = sqrt(2)` (максимальное отклонение 8.9e-16), `sum(dec_hi) = 0`
(у `dmey` отклонение 1.1e-3).

### 2.2 Условия совершенного восстановления

- Ортогональный случай (дважды сдвинутая ортонормированность):
  `sum_n h[n] h[n+2k] = delta[k]`.
- Биортогональный случай: полное произведение свёрток `P = dec_lo * rec_lo` — halfband:
  в центре `P[c] = 1`, на чётных лагах от центра ноль, `sum(P) = 2`. Пример `bior1.3`
  (проверено): `P = [-1/16, 0, 9/16, 1, 9/16, 0, -1/16]` (после центрирования), сумма 2.
  Максимальное нарушение по bior/rbio: ~1e-12 (`bior5.5`), так что таблицы PyWavelets
  не точнее 12 знаков.
- Подавление алиасинга (в z-области, с нашим обозначением H — анализ, F — синтез):
  `F0(z)H0(-z) + F1(z)H1(-z) = 0` и отсутствие искажений
  `F0(z)H0(z) + F1(z)H1(z) = 2 z^(-l)`.
  Эти формулы стандартные (из теории банков фильтров), **в PyWavelets-нормировке коэффициент
  2 и сдвиг `l` не выводились — не проверено**, задержку и масштаб нужно подогнать
  численным тестом.
- Мощностная комплементарность для ортогонального случая:
  `|H0(w)|^2 + |H0(w+pi)|^2 = 2`.
- Нулевые моменты вейвлета ψ (число `p = vanishing_moments_psi`):
  `sum_n (-1)^n n^m h[n] = 0` для `m = 0..p-1`. **Численная ловушка** (проверено): для
  db38 и sym20 прямая сумма по мономам в double даёт относительную ошибку порядка 1–60
  из-за огромных значений `n^38`; для db2, db10, coif5 ошибка ~1e-16. Для больших `p`
  проверять нужно через нули `H0` в точке `w = pi` (кратность `p`) или в long double /
  mpmath, либо с центрированной и нормированной переменной.

### 2.3 Одноуровневый DWT: точный алгоритм

Проверено на `db3`, `bior3.5`, `sym5`, `haar`, `coif2`, длины 16, 17, 23, все 8
не-периодизационных режимов:

```
x_ext = pad(x, L-1 слева, L-1 справа, mode)           L = dec_len
cA = (valid_conv(x_ext, dec_lo))[1::2]                 # нечётные индексы, начиная с 1
cD = (valid_conv(x_ext, dec_hi))[1::2]
len = floor((N + L - 1) / 2)
```

Режим `periodization` (проверено, те же вейвлеты, длины 16, 17, 23):

```
x' = x, и если N нечётна, дописать x[N-1] в конец      M = len(x')
cA[k] = sum_{j=0}^{L-1} dec_lo[j] * x'[(2k + L/2 - j) mod M],   k = 0 .. M/2-1
len = ceil(N / 2)
```

### 2.4 Многоуровневый DWT

- `wavedec` возвращает `[cA_n, cD_n, cD_{n-1}, ..., cD_1]` (док.).
- `dwt_max_level(N, L) = floor(log2(N / (L - 1)))` (док. и проверено: N=1000, L=6 → 7).
  Примеры длин (проверено, N=1000, `db4`, L=8): `symmetric` → `[14, 14, 22, 38, 69, 131,
  255, 503]`, `periodization` → `[8, 8, 16, 32, 63, 125, 250, 500]`. Суммарное число
  коэффициентов в обычных режимах больше N (избыточность на краях), а в
  `periodization` может отличаться от N на единицы при нечётных длинах.
- PyWavelets предупреждает, если `level` выше `dwt_max_level` («all coefficients will
  experience boundary effects»); в TUI показывать то же предупреждение.
- **Ловушка длины**: `waverec(wavedec(x))` для нечётного N возвращает N+1 отсчётов
  (проверено: 17 → 18). Исходную длину нужно хранить и обрезать самостоятельно.

### 2.5 SWT и MODWT

SWT (проверено на `haar`, `db3`, `sym5`, `bior3.5`, уровни 1 и 2, `N=64`):

```
уровень 1:  cA1[n] = sum_j dec_lo[j] * x[(n + L/2 - j) mod N]
уровень j:  фильтр dec_lo растянут в 2^(j-1) раз (между отсчётами нули),
            применяется к cA_{j-1} с циклическим сдвигом 2^(j-1) * L/2
```

Для `j > 2` формула экстраполирована, **не проверено**. Прочее:

- Порядок результата как у `wavedec` при `trim_approx=True`: `[cAn, cDn, ..., cD1]`
  (док.), иначе список пар `(cA_k, cD_k)` от глубокого уровня к мелкому.
- Длина должна быть кратна `2**level`; `swt_max_level(N)` — число делений N на 2 (док.,
  проверено: 1024 → 10).
- `norm=True` с `trim_approx=True` сохраняет энергию: `||x||^2 = sum ||coef||^2` (проверено
  на `db4`, 3 уровня, ошибка ~1e-14). Это то, что PyWavelets называет близким к MODWT, но
  «слегка отличающимся от опубликованной версии» и ограниченным длиной, кратной
  `2**level` (док.).
- `iswt(swt(x)) = x` (проверено, включая `bior3.5`).
- MATLAB `modwt`: по умолчанию `sym4`, периодическое продолжение, `lev = floor(log2(N))`,
  выход `(lev+1) x N`; ветка `'reflection'` удваивает длину (продолжает сигнал
  симметрично до удвоенной длины) (док.). Для ортогональных имён `modwt` берёт **вторую**
  пару фильтров из `wfilters` (док.) — то есть нормировка фильтров MODWT иная, чем у DWT.

### 2.6 Вейвлет-пакеты

Имена узлов — строки из `a`/`d` (проверено для 1D, уровень 3). Порядок `natural` —
лексикографический по пути: `aaa, aad, ada, add, daa, dad, dda, ddd`. Порядок `freq`
(по возрастанию частоты) — код Грея (проверено на уровне 3):

```
freq[i] = natural[ i XOR (i >> 1) ]
→ aaa, aad, add, ada, dda, ddd, dad, daa
```

Документация MATLAB подтверждает расхождение между естественным индексом и частотой и
приводит рекурсивный порядок (0, 1, 3, 2, 6, 7, 5, 4) для db1 (док.), это тот же код
Грея.

### 2.7 Непрерывные вейвлеты в PyWavelets

Формулы (док.): `mexh`: `psi(t) = 2/(sqrt(3) pi^(1/4)) exp(-t^2/2)(1 - t^2)`;
`morl`: `exp(-t^2/2) cos(5t)`; `cmorB-C`: `1/sqrt(pi B) exp(-t^2/B) exp(j 2 pi C t)`;
`shanB-C`, `fbspM-B-C`, `gausP`, `cgauP` — см. страницу cwt. Носитель по умолчанию
`[-8, 8]`.

Алгоритм `cwt` (проверено по исходнику 1.8.0): вейвлет интегрируется кумулятивно
(`integrate_wavelet`, `precision=12` → 2^12 точек), для каждого масштаба берётся
подвыборка интеграла по индексам с округлением вниз (floor), затем свёртка, потом
`coef = -sqrt(scale) * diff(conv)` и обрезка по центру. Следствия:

- `scale2frequency(w, s) = central_frequency(w) / s`, проверено:
  `morl` → 0.8125, `cmor1.5-1.0` при масштабе 10 → 0.1.
- Результат — приближение первого порядка к аналитическому CWT. Для сравнения нужно
  **воспроизводить тот же алгоритм** (тогда совпадение ~1e-12), а сравнение с точной
  формулой допускать только с допуском порядка дискретизации (величина не измерена,
  не проверено).

### 2.8 Пороги

(проверено на x = [-3, -1, 0.5, 2, 4], λ = 1.5)

```
hard(x)    = x * [|x| >= λ]
soft(x)    = sign(x) * max(|x| - λ, 0)
garrote(x) = x - λ^2 / x   при |x| > λ, иначе 0       (док. формулы не даёт; формула подтверждена числом)
firm(x; λ1, λ2) = 0 при |x| <= λ1;  x при |x| > λ2;
                  x * λ2 (1 - λ1/|x|) / (λ2 - λ1) иначе            (док. — запись в оригинале с x, не |x|)
```

## 3. Режимы продолжения сигнала

Определения (док.) для сигнала `x1 … xn`; формулы по индексам проверены вызовом
`pywt.pad` на `x = [1, 2, 4, 8, 16]` с отступом 3:

| Режим | Слева от `x1` | Справа от `xn` | Формула | Результат на тесте (3 слева, 3 справа) |
|---|---|---|---|---|
| `zero` | 0 | 0 | `x[1-k] = x[n+k] = 0` | `0 0 0 | … | 0 0 0` |
| `constant` | `x1` | `xn` | `x[1-k] = x1`, `x[n+k] = xn` | `1 1 1 | … | 16 16 16` |
| `symmetric` (полуотсчётная симметрия) | `x2 x1 |` | `| xn xn-1` | `x[1-k] = x[k]`, `x[n+k] = x[n+1-k]` | `4 2 1 | … | 16 8 4` |
| `reflect` (отсчётная симметрия) | `x3 x2 |` | `| xn-1 xn-2` | `x[1-k] = x[1+k]`, `x[n+k] = x[n-k]` | `8 4 2 | … | 8 4 2` |
| `periodic` | `xn-1 xn |` | `| x1 x2` | `x[1-k] = x[n+1-k]`, `x[n+k] = x[k]` | `4 8 16 | … | 1 2 4` |
| `smooth` | продолжение прямой по первой разности | то же | `x[1-k] = x1 + k (x1 - x2)`, `x[n+k] = xn + k (xn - xn-1)` | `-2 -1 0 | … | 24 32 40` |
| `antisymmetric` (полуотсчётная) | `-x2 -x1 |` | `| -xn -xn-1` | `x[1-k] = -x[k]`, `x[n+k] = -x[n+1-k]` | `-4 -2 -1 | … | -16 -8 -4` |
| `antireflect` (отсчётная) | `2x1 - x3, 2x1 - x2 |` | `| 2xn - xn-1, 2xn - xn-2` | `x[1-k] = 2 x1 - x[1+k]`, `x[n+k] = 2 xn - x[n-k]` | `-6 -2 0 | … | 24 28 30` |
| `periodization` | как `periodic`, но сигнал сначала дополняется до чётной длины повтором `xn` | | выходная длина минимальна: `ceil(N/2)` | при N=5: `8 16 16 | 1 2 4 8 16 | 16 1 2 4` |

Длины:

- Все режимы, кроме `periodization` (док. и проверено, N=10..13, L=6):
  `len(cA) = len(cD) = floor((N + L - 1) / 2)`.
- `periodization`: `ceil(N / 2)` (док.). Обратный `idwt` должен использовать тот же
  режим (док.).
- Только `periodization` даёт ортогональное преобразование (в смысле матрицы `A`) и
  выполняет Parseval (проверено на `db4`, N=64: `52.009272901103905` против
  `52.00927290110391`; в `symmetric` энергия 77.96, то есть не сохраняется).
- Остальные режимы слегка избыточны, но дают совершенное восстановление (док.).

Не проверено: поведение `pad`, когда отступ больше N (в тест-векторы обязательно
включить N < L-1, в том числе N = 1 и 2). Совпадение названий режимов с MATLAB (`sym`,
`symh`, `symw`, `zpd`, `ppd`, `per` и т.д.) **не проверено**; известно только, что
MATLAB `modwt`/`cwt` имеют `reflection` в смысле удвоения длины (док.), то есть иной
смысл, чем у `reflect` PyWavelets.

## 4. Стратегия валидации

### 4.1 PyWavelets как эталон: генерация golden-векторов

Один скрипт `tools/gen_golden.py` (вне сборки C++), который пишет файлы в бинарном
формате (`.npy` или raw float64 + JSON-манифест) и записывает в манифест версии
PyWavelets/numpy, seed и sha256. Наборы:

1. **Фильтры**: `dec_lo, dec_hi, rec_lo, rec_hi, orthogonal, symmetry,
   vanishing_moments_psi/phi` для всех 106 имён. Допуски сравнения с нашей
   факторизацией:
   - db, coif, haar: абсолютный 1e-14 (таблицы PyWavelets точны ~2e-16, проверено);
   - sym: **1e-10** (таблицы PyWavelets неточны: ошибка ортонормированности до
     1.4e-11 у `sym20`, 4.8e-12 у `sym3`, 4.3e-12 у `sym18`; в 14 из 75 ортогональных
     вейвлетов она больше 1e-13). При расхождении предпочитать собственную проверку
     ортонормированности, а не таблицу эталона. Вероятно, наши коэффициенты окажутся
     **точнее эталона**; это нужно документировать, а не «чинить»;
   - bior/rbio: 1e-11 (нарушение halfband до ~1e-12);
   - `dmey`: только как таблица, не как проверка ортогональности (ошибка
     ортонормированности 2.2e-3, ошибка PR при `wavedec/waverec` порядка 1.7e-2 на
     тестовом сигнале; флаг `orthogonal=True` вводит в заблуждение).
   Отдельный вопрос для симлетов: выбор нулей при факторизации (наименьшая асимметрия)
   и знак/обращение времени — сравнивать после приведения к соглашению из 2.1.
2. **`dwt`/`idwt`/`wavedec`/`waverec`**: матрица вейвлетов × режимов × длин.
   Вейвлеты: `haar, db2, db4, db10, sym5, coif3, bior1.3, bior3.5, bior6.8, rbio2.2,
   dmey` (+ один очень длинный, `db38`). Режимы: все 9. Длины: `1, 2, 3, L-1, L, L+1, 15,
   16, 17, 64, 1000, 1001`, чётные и нечётные. Уровни: 1 … `dwt_max_level`. Допуск:
   относительный 1e-12 для double (макс. по элементу с нормой выходного вектора),
   1e-5 для float32.
3. **SWT/ISWT/MRA**: `level` 1…4, `trim_approx` ∈ {0, 1}, `norm` ∈ {0, 1},
   `start_level` ∈ {0, 1}, длины, кратные `2**level`.
4. **Вейвлет-пакеты**: все узлы уровня 3, оба порядка, `reconstruct` после обнуления
   одного узла.
5. **CWT**: `morl`, `mexh`, `cmor1.5-1.0`, `gaus2`, `cgau2`; масштабы `[1, 2, 4, 8, 16.5]`;
   `conv` и `fft`; проверять при воспроизведении алгоритма 2.7 с допуском 1e-8 (FFT) и
   1e-11 (conv); для `float32` 1e-4. Сравнение с аналитикой — отдельный мягкий тест.
6. **Пороги**: все пять режимов + `threshold_firm`, граничные значения (`|x| == λ`),
   `substitute`, нули, комплексные данные (для soft/hard док. обещает поддержку).
7. **Свойства φ/ψ**: `wavefun(level)` — длина `(n-1)*2^level + 1` (проверено: `db2`,
   level 10 → 3073), значения сравнивать с допуском 1e-9 (каскад накапливает ошибку).

Допуски в 4.1 и 4.2 — рекомендации, кроме отдельно отмеченных измеренных величин
(ошибки таблиц PyWavelets); их нужно уточнить по первому прогону.

Рекомендация: хранить golden-файлы в репозитории только для небольшой выборки
(<= 2 МБ), остальное генерировать при CI-прогоне, если Python доступен. Версия
эталона в манифесте — чтобы при выходе PyWavelets 1.10.x видеть, что именно
изменилось.

### 4.2 Математические самопроверки без эталона

| Свойство | Как проверять | Допуск (double) |
|---|---|---|
| PR: `idwt(dwt(x)) == x` для всех режимов | случайные x, все длины, отдельно N < L | 1e-12 · sqrt(N) |
| Ортогональность: `A^T A = I` | построить матрицу `A` DWT размера N×N в режиме `periodization` (N чётно), проверить норму `A^T A - I` | 1e-12 |
| Parseval | `‖x‖² = Σ‖coef‖²` в `periodization` для ортогональных; в SWT с `norm=True` | 1e-12 |
| `sum(h0) = sqrt(2)`, `sum(h1) = 0`, `sum((-1)^n h0[n]) = 0` | прямая сумма | 1e-14 (db), 1e-10 (sym) |
| Дважды сдвинутая ортонормированность `sum h[n]h[n+2k] = δ[k]` | автокорреляция | 1e-14 (db), 1e-10 (sym) |
| Подавление алиасинга и PR через полифазные компоненты | `F0(z)H0(-z) + F1(z)H1(-z) = 0` как полиномиальное тождество | 1e-13 |
| Мощностная комплементарность `|H0(w)|^2 + |H0(w+pi)|^2 = 2` | сетка ω | 1e-12 |
| Halfband для биортогональных | `dec_lo * rec_lo`: центр 1, чётные лаги 0, сумма 2 | 1e-11 |
| Нулевые моменты | ортогональные: через нули `H0` в `w = pi`; для малых `p` — прямые суммы; для db38 / sym20 нельзя прямой суммой в double (2.2) | 1e-12 (малые p) |
| Воспроизведение полиномов | `dwt` полинома степени `< p` (`p` = число нулевых моментов) даёт нулевые детали внутри сигнала, вдали от краёв | 1e-9 |
| Линейная фаза у bior | `dec_lo[k] = dec_lo[n-1-k]` | 1e-15 |
| Уравнение масштабирования | `φ(t) = sqrt(2) Σ h[k] φ(2t - k)`, `∫φ = 1`, `‖ψ‖ = 1`, `ψ ⊥ φ` на сетке каскада | 1e-6 |
| Инвариантность SWT к сдвигу | `swt(roll(x, s)) == roll(swt(x), s)` | 1e-13 |
| Аддитивность MRA | `Σ компонент = x` | 1e-12 |
| Сравнение с медленной O(N²) матричной реализацией | рандомизированно | 1e-12 |
| Побитовая воспроизводимость | один и тот же вход → одно и то же на разных потоках/SIMD-вариантах | точное совпадение или 1 ulp |

Также: property-based / fuzz по (вейвлет, режим, N, уровень), тест на отсутствие
чтения за границами (sanitizers), float32 против float64.

### 4.3 Тестовые сигналы и бенчмарки

Стандартный набор — сигналы Donoho–Johnstone (Biometrika 81(3):425–455, 1994; продолжение:
JASA, 1995). Определения проверены по исходнику `pywt.data.demo_signal` (переработка
`MakeSignal` из Wavelab, «provided with permission of Dr. Donoho»), сетка `t = i/n`,
`i = 1..n`:

```
Blocks:     f(t) = Σ_j h_j (1 + sgn(t - t_j)) / 2
            t = (.1 .13 .15 .23 .25 .4 .44 .65 .76 .78 .81)
            h = (4 -5 3 -4 5 -4.2 2.1 4.3 -3.1 2.1 -4.2)

Bumps:      f(t) = Σ_j h_j (1 + |(t - t_j)/w_j|)^(-4)
            t = как у Blocks
            h = (4 5 3 4 5 4.2 2.1 4.3 3.1 5.1 4.2)
            w = (.005 .005 .006 .01 .01 .03 .01 .01 .005 .008 .005)

HeaviSine:  f(t) = 4 sin(4πt) - sgn(t - 0.3) - sgn(0.72 - t)

Doppler:    f(t) = sqrt(t (1 - t)) · sin(2π · 1.05 / (t + 0.05))
```

Ловушки: (1) в Blocks предпоследняя высота `2.1`, а в Bumps `5.1`; сторонний
пересказ в результатах поиска расходился с исходником, верить исходнику. (2) WaveThresh
`DJ.EX` предупреждает, что значения могут не совпадать с Wavelab (док.); MATLAB `wnoise`
перенормирует сигнал так, чтобы его стандартное отклонение равнялось `sqrtsnr`, и
добавляет шум N(0,1) (док.). Для воспроизводимости брать версию Wavelab/PyWavelets и
фиксировать нормировку. (3) Оригинальные формулы в статье 1994 года **напрямую не
сверены** (доступ к тексту статьи не получен, не проверено).

Типовая постановка шумоподавления: `n = 1024`, шум N(0,1), RSNR = 7 (значения по
умолчанию в WaveThresh `DJ.EX(n=1024, signal=7, rsnr=7)`, док.); метрика — MSE или SNR
после подавления для каждого метода порога. Универсальный порог в этой постановке
эталонный, описан у Donoho–Johnstone.

Для аудио проверенных стандартных наборов в этом обзоре не найдено (**не проверено**):
использовать синтетику (свип, импульсы, шум, ступенька, чистые тоны, суперпозиция
тона и транзиента) и короткие свободные клипы; MATLAB-образец речи `mtlb` не
распространяется с нашим кодом.

### 4.4 Предупреждения об эталоне

- Таблицы PyWavelets не идеальны (sym до 1.4e-11, dmey 2.2e-3), и часть вейвлетов
  (`dmey`) помечена ортогональными, но не является ими.
- CWT в PyWavelets — приближение первого порядка (2.7).
- Версия эталона влияет на результат для крайних случаев (см. 1.10.0, `smooth` и
  `antisymmetric` с нулевым отступом).

### 6.1 Что показывают приложения MATLAB (док.)

- **Wavelet Signal Analyzer**: график декомпозиции и реконструкции, коэффициенты,

  по всем уровням; для недециммированных — дисперсия коэффициентов; для выбранного
  уровня или узла — автокорреляция и гистограмма коэффициентов. Настройки: семейство

  интервалы. Экспорт коэффициентов, сжатых коэффициентов и сигнала; генерация скрипта.

  выходных аргументов рисует скалограмму `|CWT|` в координатах «время–логарифмическая
  частота» с конусом влияния; нормировка L1, так что синусоида единичной амплитуды даёт
  величину около 1 (док.).

### 6.2 Терминальные аудио-инструменты (по обзору поиска; детали не проверены)

- **cava** (проверено по README): столбчатый анализатор спектра; для вертикального
  разрешения использует частичные блоки Unicode U+2581–U+2587; поддержка многих
  источников звука (PipeWire, PulseAudio, ALSA, JACK, CoreAudio и др.), темы и
  градиенты.
- **soundscope** (Rust, Ratatui): FFT-спектр, осциллограмма, измеритель LUFS и true
  peak, темы.
- **sgram-tui**: «водопад» спектрограммы для WAV и микрофона, экспорт PNG, справка по
  `h`/`F1`.
- **prism-tui**: «стойка» из восьми анализаторов, настраиваемые шкалы спектрограммы.
- Мышь ни в одном из просмотренных результатов не упоминается (не проверено) — это
  реальное отличие нашего TUI.

### 6.3 Что взять

1. Три режима экрана: анализ (скалограмма + MRA), деноизинг (до/после), поддиапазоны
   (список уровней с чекбоксами «входит в реконструкцию»). Из Signal Multiresolution
   Analyzer берём подпись теоретической полосы пропускания и относительную энергию
   каждого уровня.
2. Мышь: клик по уровню включает/выключает его, перетаскивание порога на графике,
   колесо для масштаба по времени, выделение интервала для проигрывания.
3. Живое сравнение: A/B-переключатель «исходный/обработанный» с одинаковой громкостью,
   разностный сигнал (`x - x̂`) как отдельная дорожка, SNR/MSE до и после.
4. Отображение: полублочные символы Unicode (как у cava) или брайлевские точки
   (2×4 на ячейку) для осциллограммы; скалограмма цветом 256/truecolor. Графические
   протоколы терминала (kitty, sixel) в обзоре не изучались (не проверено).
5. Конус влияния и пометка краевых коэффициентов (когда `level` выше `dwt_max_level`) —
   как предупреждение в строке состояния.
6. Экспорт **воспроизводимой команды** и рецепта (аналог «generate script» во всех
   приложениях MATLAB): семейство, режим, уровень, пороги, метод оценки шума; CLI
   выполняет тот же рецепт без TUI.
7. Прогресс долгих операций (CWT, пакеты, MRA): живая полоса прогресса и отмена.
8. Карточка вейвлета: φ, ψ (`wavefun`), АЧХ четырёх фильтров, число нулевых моментов,
   симметрия, ортогональность, длина.
9. Карточка банка фильтров из факторизации: корни полинома, выбор нулей внутри/вне
   круга (наш уникальный сценарий), проверка PR/алиасинга в реальном времени.
